## Научная цель

Разработка и верификация комплексной математико-алгоритмической модели геометрического образа береговой линии, сочетающей фрактальные свойства и динамику изменения под воздействием эрозионных процессов.

**Ключевые задачи:**

1. Валидация геометрии входных береговых линий с проверкой топологической корректности
2. Геодезически корректное измерение длины с учётом кривизны Земли
3. Анализ фрактальных свойств методом box-counting с повышенной статистической устойчивостью
4. Геоморфологическое моделирование волновой эрозии с учётом:
   - fetch-расстояний и экспозиции берега
   - реальной батиметрии (GEBCO данные)
   - литологического состава пород
   - временной динамики (штормы, сезонность, климатические сценарии)

## 🧩 CLI

### Структура команд

```bash
# Источник данных
lito source                    # проверка источника данных

# Анализ и моделирование
lito dimension                 # фрактальный анализ (box-counting)
lito erosion                   # геоморфологическое моделирование эрозии
lito all                        # полный пайплайн: валидация + фрактальный + эрозия

# Калибровка и верификация
lito benchmark list            # список калибровочных участков
lito benchmark init           # инициализация участков Чёрного моря
lito benchmark show --site ID # детальная информация об участке
lito benchmark calibrate       # калибровка параметров модели
lito benchmark analyze         # полный статистический анализ

# Утилиты
lito completion bash|zsh       # генерация скриптов автодополнения
```

### Основные флаги

```bash
# Базовые параметры
--output PATH                # директория для выходных файлов
--iterations N               # число итераций organic Koch (0-10)
--steps N                    # число шагов эрозии

# Фрактальный анализ
--seed INT                   # seed для воспроизводимости
--angle-jitter FLOAT         # максимальное отклонение угла (градусы)
--height-jitter FLOAT        # максимальное отклонение высоты (доля)

# Геоморфологическое моделирование
--erosion-strength FLOAT     # базовый отступ берега (метры)
--wave-direction FLOAT       # направление волн (градусы от севера)
--wind-speed FLOAT           # скорость ветра (м/с)
--fetch-spread FLOAT         # полуширина сектора fetch (градусы)
--bathymetry PATH           # путь к файлу батиметрии
--lithology PATH            # путь к файлу литологии
--enable-lithology          # включить модуляцию по породам

# Временная динамика
--target-years N             # целевой период моделирования (годы)
--years-per-step FLOAT       # лет за шаг моделирования
--storm-probability FLOAT    # вероятность шторма за шаг [0-1]
--storm-intensity FLOAT      # множитель силы шторма [1.0-10.0]
--sea-level-rise FLOAT       # подъём уровня моря (м/год)
--enable-seasonality        # включить сезонные колебания
```

Команды `erosion` и `all` действительно загружают указанные батиметрию и
литологию. Указание `--lithology` автоматически включает литологическую
модуляцию; `--enable-lithology` использует профиль
`data/black-sea-lithology.json` по умолчанию. При `--target-years` команда
`all` запускает временную модель со штормами, сезонностью и подъёмом уровня
моря, а не обычный дискретный цикл.

Экспорты подключаются непосредственно к этим командам:

```bash
./lito erosion --output-csv erosion.csv --output-gif erosion.gif
./lito all --target-years 20 --output-csv all.csv --output-gif all.gif
```

Относительные CSV и GIF сохраняются в `output/csv/` и `output/gif/` внутри
каталога `--output`; параметры `--csv-format`, `--gif-fps` и `--gif-skip`
управляют форматом и анимацией. Подробности находятся в
[`docs/cli-experiments.md`](docs/cli-experiments.md).

## 🛠 Установка и запуск

```bash
# Клонирование
git clone https://github.com/Nickitas/litora-cli.git
cd litora-cli

# Сборка
go build -o lito ./cmd/lito

# Или через Makefile
make build

# Запуск
./lito --help
```

### Автоматическая загрузка батиметрии

```bash
# Загрузка реальных данных GEBCO для Чёрного моря
make bathymetry

# Или напрямую
go run cmd/download-bathymetry/main.go
```

Данные сохраняются в `data/black-sea-bathymetry.json` и автоматически используются при моделировании эрозии.

## Сценарии использования

### 1. Инспекция источника данных

```bash
# Проверка источника и метаданные
./lito source

# Сохранение snapshot
./lito source --output ./data/snapshots

# Принудительное обновление
./lito source --refresh
```

### Рабочие артефакты и исследовательские материалы

Каталог `output/` предназначен только для локальных результатов запусков и не
содержит версируемых SVG, CSV, GIF или отчётов. Каталоги `data/cache/` и
`data/snapshots/` также являются локальным кэшем и снимками источника; при
необходимости они создаются командами заново.

Исследовательские заметки в `research-notes/`. Они не входят в основной
контур выполнения CLI.

Решения по бывшим экспериментальным модулям описаны в
`docs/maintenance/quarantine.md`: неиспользуемые concurrency и TIN удалены, а
транспорт наносов, литология и расширенный SVG оставлены в активных доменном и
рендерном слоях.

### 2. Фрактальный анализ

```bash
# Базовый анализ (5 итераций по умолчанию)
./lito dimension --iterations 6

# С настройками генерации
./lito dimension \
  --iterations 8 \
  --seed 42 \
  --angle-jitter 18 \
  --height-jitter 0.25
```

**Результаты:**

- Таблица сходимости фрактальной размерности по итерациям
- Анализ стабильности (R², разброс)
- Сравнение с теоретическим значением Koch (D ≈ 1.262)

### 3. Геоморфологическое моделирование эрозии

```bash
# Базовая эрозия (5 шагов)
./lito erosion --steps 5 --erosion-strength 50

# С батиметрией
make bathymetry
./lito erosion \
  --steps 10 \
  --erosion-strength 50 \
  --bathymetry data/black-sea-bathymetry.json \
  --wave-direction 45

# С временной динамикой
./lito erosion \
  --target-years 20 \
  --years-per-step 2 \
  --storm-probability 0.2 \
  --storm-intensity 2.5 \
  --enable-seasonality
```

### 4. Полный пайплайн

```bash
# Все анализы вместе
./lito all --iterations 4 --steps 10

# С временными параметрами
./lito all \
  --iterations 4 \
  --steps 10 \
  --target-years 20 \
  --storm-probability 0.15 \
  --enable-seasonality
```

### 5. Калибровка модели

```bash
# Инициализация benchmark участков
./lito benchmark init

# Список участков
./lito benchmark list

# Калибровка для участка
./lito benchmark calibrate --site=odessa-coast-ua

# Полный анализ
./lito benchmark analyze --site=kobuleti-ge

# Горячие точки эрозии
./lito benchmark hotspots \
  --site=odessa-coast-ua \
  --erosion-strength 15 \
  --wave-direction 22

# Сценарный анализ
./lito benchmark scenarios --site=kobuleti-ge
```

## Выходные данные

SVG-файлы команды `dimension` используют компактный научный режим: на карте
остаётся один текущий контур модели, аналитическая сетка box-counting, номер
итерации, масштаб и стороны света. Подробные графики, валидация и метрики
сохраняются в JSON-результатах и не перегружают карту.
SVG-файлы `erosion` оформляются аналогично: один текущий контур шага,
эрозионная сетка, разреженное поле направления волн, масштаб и оси OX/OY.
Начиная с первого шага береговые сегменты дополнительно окрашиваются по
изменению положения: красно-оранжевый — размыв, синий — накопление, серый —
нейтральная зона. Единая шкала сохраняется между шагами; единицы отображаются
как `м/шаг` или `м/год`.
Текстовые блоки научной карты имеют единое левое выравнивание.
Метаданные и легенды размещаются в отдельной области над картой, чтобы не
перекрывать друг друга и не ухудшать читаемость координатной сетки.
Оси OX/OY и масштаб вынесены за пределы клиппинга карты и сохраняются при
изменении параметров сетки.
JSON-метрики содержат блок `reproducibility` с версией схемы, системой
координат, референсной точкой проекции и единицами измерения. В него также входят SHA-256 входной
геометрии, число точек, тип сетки, размер ячейки и буферная зона.
Блок `report_metadata` содержит дату формирования, версию входной геометрии
SHA-256, источник данных, идентификатор эксперимента, проекцию и её референсную
точку; эти сведения также видны в заголовке SVG.
Для `dimension` дополнительно сохраняются все уровни `ε`, значения `N(ε)` и
смещения расчётной сетки.
Легенда box-counting на карте показывает плотность покрытия ячеек, тёмной
рамкой отмечает представительный масштаб внутри регрессионного окна и содержит
ссылку на соответствующий `dimension_loglog_*.svg`.
Для каждого шага `dimension` формируется отдельный log-log SVG-график с
регрессионным окном, а JSON содержит доверительный интервал и локальные
наклоны для оценки устойчивости размерности.
Для `erosion` JSON дополнительно содержит среднее подписанное и максимальное
абсолютное изменение береговой линии для каждого шага, а также число
контрольных наблюдений и совпадений с ними. На карте зелёные контрольные точки
означают согласие с наблюдением в пределах погрешности, оранжевые — расхождение.
Для `dimension` отображается 95%-й доверительный интервал оценки размерности.
