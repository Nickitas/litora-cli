## Научная цель

Разработка и верификация комплексной математико-алгоритмической модели геометрического образа береговой линии, сочетающей фрактальные свойства и динамику изменения под воздействием эрозионных процессов.

**Ключевые задачи:**

1. Валидация геометрии входных береговых линий с проверкой топологической корректности
2. Геодезически корректное измерение длины с учётом кривизны Земли
3. Анализ фрактальных свойств методом box-counting с повышенной статистической устойчивостью
4. Инженерное одномерное моделирование вдольберегового переноса CERC с:
   - фактическим рядом `Hs`, `Tp`, направления и длительности волн
   - дисперсией, рефракцией, shoaling и критерием разрушения
   - батиметрией с проверяемым паспортом и пространственным балансом наносов в м³
   - воспроизводимым источником входных волновых данных
5. Построение четырёхугольных 2D-сеток всей акватории Чёрного моря открытым
   генератором Gmsh и выбор алгоритма по сохранению локальных площадей берега

## 🧩 CLI

### Структура команд

Справка всех команд и стандартный флаг `--help` полностью локализованы на
русский язык.

```bash
# Источник данных
lito source                    # проверка источника данных
lito map black-sea             # обзорная карта всего побережья Чёрного моря

# Анализ и моделирование
lito dimension                 # фрактальный анализ (box-counting)
lito koch-demo                 # учебная синтетическая Кох-подобная серия
lito mesh                      # генерация и сравнение 2D-сеток всей акватории
lito seabed render             # карты глубин, 3D-рельеф и профили дна
lito seabed adapt              # поле размера адаптивной сетки 200–1000 м
lito erosion                   # геоморфологическое моделирование эрозии
lito all                        # полный пайплайн: валидация + фрактальный + эрозия

# Калибровка и верификация
lito benchmark list            # список калибровочных участков
lito benchmark init           # инициализация участков Чёрного моря
lito benchmark show --site ID # детальная информация об участке
lito benchmark calibrate       # историческая эвристическая калибровка
lito benchmark analyze         # полный статистический анализ
lito calibrate-cerc            # физическая калибровка коэффициента CERC

# Утилиты
lito completion bash|zsh       # генерация скриптов автодополнения
```

### Основные флаги

```bash
# Базовые параметры
--input PATH                 # использовать только этот локальный файл
--source-url URL             # явно включить удалённый источник (без --input)
--output PATH                # директория для выходных файлов
--steps N                    # число первых состояний волнового ряда (0 — все)

# Только учебная команда koch-demo
--iterations N               # число итераций органического Коха
--seed INT                   # seed для воспроизводимости
--angle-jitter FLOAT         # максимальное отклонение угла (градусы)
--height-jitter FLOAT        # максимальное отклонение высоты (доля)

# Инженерная CERC-модель
--wave-input PATH            # обязательный CSV/JSON фактических состояний волн
--wave-source TEXT           # источник CSV, если он отсутствует в JSON
--bathymetry PATH            # обязательная батиметрия с соседним .metadata.json
--bathymetry-resolution FLOAT # фактический шаг батиметрической сетки (градусы)
--breaking-index FLOAT       # индекс разрушения H_b/h_b
--berm-height FLOAT          # высота бермы активного профиля (м)
--closure-depth FLOAT        # глубина замыкания активного профиля (м)
--porosity FLOAT             # пористость наносов
--cerc-coefficient FLOAT     # коэффициент CERC
--max-bathymetry-gap FLOAT   # предел поиска реальной точки глубины (м)
--left-boundary-transport FLOAT  # поток на левой границе сегмента (м³/с)
--right-boundary-transport FLOAT # поток на правой границе сегмента (м³/с)
--sediment-sources PATH      # JSON измеренных источников/стоков наносов
--structures PATH            # JSON сооружений на гранях расчётных ячеек

# Расчётные 2D-сетки
--cell-sizes LIST            # целевые рёбра, например 1000,500,300,200 м
--boundary-details LIST      # метрические допуски детализации берега
--generators LIST            # алгоритмы Gmsh для сравнения
--gmsh PATH                  # явный путь к локальному Gmsh
--max-cells N                # защитный предел ячеек одного запуска
--generator-timeout 5m      # лимит времени одного алгоритма; отказ попадёт в отчёт
```

Команды `erosion` и `all` используют только явно загруженный волновой ряд:
наблюдения, реанализ или прогноз с указанным происхождением.
Самый простой запуск не требует путей: `./lito all` (или `./lito erosion`)
автоматически выбирает готовый открытый стартовый набор Сочи. В нём есть
валидируемый локальный кэш волнового ряда и батиметрии; при первом отсутствии
кэша программа скачает его сама. Это сценарий со статусом `demo`, а не
исследовательский набор. Для обновления данных используйте
`--refresh`. Если вручную задан хотя бы один входной файл Чёрного моря, полный
комплект реальных данных остаётся обязательным. Время задаётся полем
`duration_hours` каждой записи, поэтому умолчательные скорость ветра,
fetch-факторы и случайные штормы не участвуют в расчёте CERC. Итоговый
пространственный баланс сохраняется в `output/erosion/longshore-cerc.json`.
Формат данных, источники и границы применимости приведены в
[`docs/cerc-one-line-model.md`](docs/cerc-one-line-model.md).
Требования к происхождению батиметрии и ограничения alpha-литологии описаны в
[`docs/data-provenance.md`](docs/data-provenance.md).

Для немедленной технической проверки используйте готовый набор из
[`data/examples`](data/examples/README.md). Он содержит открытый прогноз волн
и фактические глубины, но не заменяет изыскательские данные участка.

Для автоматического сценария Чёрного моря достаточно выполнить:

```bash
./lito all
# или: ./lito erosion
# обновить открытые входные данные: ./lito all --refresh
```

Команда получает прогноз волн Open-Meteo Marine и глубины EMODnet, сохраняет
их в `data/black-sea/sochi/`, фиксирует происхождение в `manifest.json` и
выполняет первые 24 часа расчёта. Также она запрашивает из OpenStreetMap
геометрию бун и волноломов; только берегопримыкающие явно размеченные буны
автоматически получают нулевой пропуск, остальные объекты не получают
выдуманный коэффициент. В `longshore-cerc.json`, метриках и SVG он получает
`scenario_status: "demo"` и явные `usage_limitations`. Успешное завершение
расчёта не повышает этот статус. Сценарий нельзя использовать для оценки
годового размыва, калибровки или публикации; для исследовательского вывода
необходимы архив наблюдений либо реанализ и данные конкретного участка.
Тот же демонстрационный сценарий можно включить явно: `./lito all --black-sea-sochi`.

### Обзорная карта Чёрного моря

Команда ниже не требует файлов пользователя: она получает открытый контур
MarineRegions, использует локальный кэш при повторном запуске и создаёт SVG и
GeoJSON для ГИС. Участок Сочи, используемый стартовой CERC-моделью, выделен
отдельным слоем.

```bash
./lito map black-sea
# обновить кэш открытого контура:
./lito map black-sea --refresh
```

Результаты находятся в `output/black-sea-map/svg/black-sea-coast.svg` и
`output/black-sea-map/metrics/black-sea-coast.geojson`. Это обзорная карта
границы моря и его побережья, а не точный локальный контур для моделирования
или проектирования. Подробнее — в [документации карты](docs/black-sea-map.md).

Lito намеренно не содержит каталога других морей, озёр или рек. Береговые и
батиметрические координаты вне зафиксированной области Чёрного моря
отклоняются при загрузке.

Каждый расчёт CERC сохраняет в `longshore-cerc.json` `scenario_status` и
`usage_limitations`, путь, SHA-256 и статус паспорта батиметрии, фактическое
покрытие волнового ряда, число и разрешение точек батиметрии, а также дистанции до
ближайших измерений. Ненулевое расстояние означает, что использована не
интерполяция, а ближайшая реальная точка. Торцы сегмента по умолчанию закрыты,
но их можно заменить измеренными потоками флагами границ. Внешнее питание
пляжа, устьевой приток или дноуглубление задаются отдельно через
`--sediment-sources`; они также входят в баланс массы и итоговый JSON.
Для бун, волноломов и портов используйте `--structures` с обоснованным
коэффициентом пропуска: это блокирует вдольбереговый поток, но не заменяет
отдельную 2D-модель дифракции волн.

Для калибровки коэффициента CERC по независимым годовым скоростям смещения
берега используйте `lito calibrate-cerc`. Команда требует волновой ряд не
короче репрезентативного года и сохраняет ранжированный отчёт в
`output/erosion/cerc-calibration.json`. Формат наблюдений и пример запуска — в
[`docs/cerc-one-line-model.md`](docs/cerc-one-line-model.md).

Экспорты подключаются непосредственно к этим командам:

```bash
./lito erosion --output-csv erosion.csv --output-gif erosion.gif
./lito all --target-years 20 --output-csv all.csv --output-gif all.gif
```

Относительные CSV и GIF сохраняются в `output/csv/` и `output/gif/` внутри
каталога `--output`; параметры `--csv-format`, `--gif-fps` и `--gif-skip`
управляют форматом и анимацией. Подробности находятся в
[`docs/cli-experiments.md`](docs/cli-experiments.md).

## 🛠 Установка и запуск

```bash
# Клонирование
git clone https://github.com/Nickitas/litora-cli.git
cd litora-cli

# Сборка
go build -o lito ./cmd/lito

# Или через Makefile
make build

# Запуск
./lito --help
```

### Подготовка батиметрии с паспортом

```bash
# Открыть официальный каталог и получить точный URL регионального NetCDF
go run cmd/bathymetry/main.go download

# Сохранить исходник, checksum и производный набор с паспортом
cmd/bathymetry/convert/download_bathymetry.sh \
  'ТОЧНЫЙ_URL_NETCDF_ИЗ_GEBCO' GEBCO_2026 \
  '10.5285/4f68d5c7-45eb-f999-e063-7086abc036fa' \
  output/source/black-sea-bathymetry-gebco2026-0.01deg-derived.json
```

Батиметрия больше не подставляется автоматически. Прежний смешанный набор
перенесён в `data/legacy/` и не является подтверждённым продуктом GEBCO.

## Сценарии использования

### 1. Инспекция источника данных

```bash
# Проверка источника и метаданные
./lito source

# Сохранение snapshot
./lito source --output ./data/snapshots

# Принудительное обновление
./lito source --refresh
```

### Рабочие артефакты и исследовательские материалы

Каталог `output/` предназначен только для локальных результатов запусков и не
содержит версируемых SVG, CSV, GIF или отчётов. Каталоги `data/cache/` и
`data/snapshots/` также являются локальным кэшем и снимками источника; при
необходимости они создаются командами заново.

Исследовательские заметки в `research-notes/`. Они не входят в основной
контур выполнения CLI.

Решения по бывшим экспериментальным модулям описаны в
`docs/maintenance/quarantine.md`: неиспользуемые concurrency и TIN удалены, а
транспорт наносов, литология и расширенный SVG оставлены в активных доменном и
рендерном слоях.

### 2. Фрактальный анализ

```bash
# Научная оценка по неизменённой наблюдаемой линии
./lito dimension --input data/black-sea-coastline.geojson

# Отдельная учебная проверка на синтетических Кох-подобных кривых
./lito koch-demo \
  --iterations 8 \
  --seed 42 \
  --angle-jitter 18 \
  --height-jitter 0.25
```

**Результаты:**

- `dimension`: одна оценка исходных наблюдений, R², разброс локальных наклонов,
  доверительный интервал и аудит диапазона масштабов;
- `koch-demo`: синтетическая серия роста сложности и длины, где допустимо
  справочное сравнение с классической кривой Коха.

`dimension` не вызывает генератор Коха и не сравнивает природный контур с
`log(4)/log(3)`. Оценка box-counting зависит от разрешения данных и
регрессионного окна и сама по себе не доказывает строгую фрактальность берега.
Подробные границы интерпретации описаны в
[документе о научном контуре](docs/fractal-analysis-scope.md).

## Расчётные 2D-сетки

Официальный открытый Gmsh устанавливается локально, без изменения системных
каталогов:

```bash
./scripts/install-gmsh.sh
```

Полный эксперимент по замечанию научного руководителя:

```bash
./lito mesh \
  --cell-sizes 1000,500,300,200 \
  --boundary-details 1000,500,300,200 \
  --allow-large
```

Команда по умолчанию использует весь кэшированный полигон Чёрного моря
MarineRegions, включая островные отверстия, и сравнивает Delaunay,
Frontal-Delaunay for Quads и Packing of Parallelograms. Для каждого масштаба
она сохраняет полную четырёхугольную сетку MSH, GEO-сценарий, журнал, SVG и
ранжированный JSON/TSV. Основной критерий `Σ|ΔS|` суммирует абсолютные локальные
изменения площадей заливов, кос и других особенностей до компенсации знаков.

Фрактальную оценку всего наблюдаемого контура можно отдельно восстановить
командой `./lito dimension --full-black-sea`. Аналитическая box-counting-сетка
не подменяется расчётной сеткой Gmsh. Аналогично одномерная CERC-модель остаётся
локальной и не называется двумерной только из-за наличия сетки. Методика,
формула рейтинга, оценка ресурсов и структура файлов описаны в
[`docs/mesh-generation.md`](docs/mesh-generation.md).

## Модель рельефа морского дна

Плоская расчётная сетка служит геометрическим каркасом, а слой `seabed`
назначает ей проверенные глубины и производные характеристики. План построения
3D-рельефа, адаптации размера ячеек и научной проверки описан в
[`todo/DEVELOPMENT_PLAN.md`](todo/DEVELOPMENT_PLAN.md).
Задачи `ARCH-01`, `DATA-01`, `DATA-02`, `GEO-01`, `BATHY-01`, `BATHY-02`,
`BATHY-03`, `EXPORT-01`, `EXPORT-02`, `VIEW-01`–`VIEW-03` и `ADAPT-01`
выполнены: соглашения о
знаке, вертикальной системе, NoData, полях узлов/ячеек и форматах закреплены в
[`docs/adr/seabed-data-contract.md`](docs/adr/seabed-data-contract.md), а
машинная схема отчёта — в
[`docs/schemas/lito-seabed-v1.schema.json`](docs/schemas/lito-seabed-v1.schema.json).
Для батиметрии зафиксированы основной источник GEBCO_2026 с TID и контрольный
EMODnet DTM 2024; решение, лицензии и ограничения описаны в
[`docs/bathymetry-source-selection.md`](docs/bathymetry-source-selection.md).
Итоговые узлы сетки теперь содержат `X/Y` в LAEA и `longitude/latitude` в
WGS 84; методика обратного преобразования и предел ошибки приведены в
[`docs/mesh-generation.md`](docs/mesh-generation.md#равноплощадная-проекция).
Новый доменный слой назначает узлам точные, билинейные или ближайшие значения,
сохраняет NoData как пустое значение, отделяет внешний берег, острова и
открытые границы, вводит береговой ноль и плавную переходную полосу без новых
провалов. Алгоритм и диагностический журнал описаны в
[`docs/bathymetry-coastline-reconciliation.md`](docs/bathymetry-coastline-reconciliation.md).
Для принятых четырёхугольных ячеек рассчитываются площадь, средняя и предельные
глубины, уклон, экспозиция, шероховатость и настраиваемый морфометрический
регион. Формулы и стандартные пороги 20/200/2000 м описаны в
[`docs/seabed-cell-derivatives.md`](docs/seabed-cell-derivatives.md).
Принятая модель сохраняется в Gmsh MSH 2.2 с `Z = elevation_m`, физическими
группами границ, восемью блоками `$NodeData` и одиннадцатью блоками
`$ElementData`. Метаданные `lito-seabed/v1` отличают её от плоской схемы
`lito-mesh/v1`; старый MSH без маркера читается как legacy-flat и не получает
ложную нулевую глубину. Формат, таблицы кодов и правила round-trip описаны в
[`docs/seabed-msh-export.md`](docs/seabed-msh-export.md).

Для ParaView создаётся `black-sea-depth.vtu`: четырёхугольники VTK используют
трёхмерные точки `X/Y/elevation_m`, узловые и ячеечные скаляры повторяют MSH,
единицы записываются как `UNITS_LABEL`, а системы координат и вертикальный
датум — в `FieldData`. Единый экспортный набор также содержит `nodes.csv`,
`cells.csv`, `profiles.csv` и `export-metadata.json`; идентификаторы узлов и
ячеек проверяются обратным чтением. Формат описан в
[`docs/seabed-vtu-csv-export.md`](docs/seabed-vtu-csv-export.md).

VIEW-01, VIEW-02 и VIEW-03 используют одну воспроизводимую подкоманду:

```bash
./lito seabed render
```

Она создаёт `output/seabed/svg/bathymetry-overview.svg` с непрерывной
числовой шкалой глубины, подписанными изобатами, берегом, масштабом,
источником, вертикальной системой и долей NoData. Внутренние рёбра на общей
карте скрыты; это позволяет различить шельф, склон и глубоководную котловину
без плотной паутины. Расшифровка цветов, линий и ограничений приведена в
[`docs/bathymetry-overview-map.md`](docs/bathymetry-overview-map.md).

Второй результат `output/seabed/svg/mesh-details.svg` показывает без
прореживания три фрагмента фактической сетки: участок максимальной локальной
кривизны берега, шельфовую глубину и максимальный уклон материкового склона.
Для каждого окна подписаны минимум, среднее и максимум длины ребра, глубина и
геометрическое качество четырёхугольников. Красный цвет означает сильное
искажение формы, зелёный — близость к квадрату; это не оценка достоверности
батиметрии. Алгоритм выбора и чтение рисунка описаны в
[`docs/bathymetry-mesh-details.md`](docs/bathymetry-mesh-details.md).

VIEW-03 добавляет `output/seabed/svg/seabed-3d.svg` и
`output/seabed/svg/profiles.svg`. 3D-вид использует фактические узловые отметки
и по умолчанию преувеличивает вертикаль в 40 раз только при проецировании в
SVG; коэффициент всегда подписан, а `--vertical-exaggeration 1` включает
натуральный метрический режим. Три профиля автоматически идут от западного,
восточного и северного внешнего берега к глубоководному ядру по рёбрам сетки.
Точки показывают узловые выборки, линия между ними — интерполированную
поверхность. Трассы и их значения записываются в `profiles.csv`. Подробное
описание приведено в
[`docs/bathymetry-3d-profiles.md`](docs/bathymetry-3d-profiles.md).

ADAPT-01 добавляет отдельную команду:

```bash
./lito seabed adapt
```

Она рассчитывает поле требуемой длины ребра `h(x,y)` по расстоянию до внешнего
берега и островов, дискретному повороту береговой линии и максимальному уклону
инцидентных ячеек BATHY-03. Базовые значения составляют `200–300 м` у берега,
`500 м` на шельфе и до `1000 м` на ровном глубоководье. Отношение соседних
значений ограничено `1.25`, а скорость роста — `0.15 м/м`.

Команда создаёт `output/seabed/adaptive/size-field.csv`, машинный отчёт
`size-field.json` и карту `output/seabed/svg/size-field.svg`. CSV сохраняет
каждый исходный признак, отдельные вклады формулы, размер до и после
согласования. На этом этапе Gmsh не запускается: новая адаптивная сетка будет
построена в ADAPT-02. Формулы, интерпретация карты и контрольные показатели
описаны в
[`docs/adaptive-size-field.md`](docs/adaptive-size-field.md).

## Статус параметрических сценариев

`lito benchmark scenarios` выполняет **параметрические сценарии усиления
воздействия**. Предустановки содержат вручную заданные значения ветра, подъёма
уровня моря и штормовых множителей. Они не являются реализациями RCP4.5,
RCP8.5 или прогнозами для конкретных календарных лет.

Каждый запуск сохраняет версионированный JSON-отчёт в
`output/benchmark/parametric-scenarios.json` либо под относительным именем,
переданным через `--output`. В конфигурации каждого набора явно записываются
`parameter_basis: "manual"`, `source: null` и
`sea_level_rise_proxy_m_per_year`. Контракт проверяется по
[`docs/schemas/parametric-scenarios-v2.schema.json`](docs/schemas/parametric-scenarios-v2.schema.json),
а числовые диапазоны валидируются до запуска моделирования.

Для климатического моделирования проекту потребуются документированные
временные ряды уровня моря и волнения, распределения штормов, изменение
ветрового и волнового режима, а также явные источники и версии каждого
сценарного параметра. Текущая реализация и границы её интерпретации описаны в
[`docs/parametric-impact-scenarios.md`](docs/parametric-impact-scenarios.md).

## Выходные данные

SVG-файлы команды `dimension` используют компактный научный режим: на карте
остаётся исходный наблюдаемый контур, аналитическая сетка box-counting,
масштаб и стороны света. Подробные графики, валидация и метрики
сохраняются в JSON-результатах и не перегружают карту.
Файлы `koch_demo_*.svg` относятся только к учебной синтетической серии и
содержат явное предупреждение об ограничениях интерпретации.
SVG-файлы `erosion` оформляются аналогично: один текущий контур шага,
эрозионная сетка, разреженное поле направления волн, масштаб и оси OX/OY.
Начиная с первого шага береговые сегменты дополнительно окрашиваются по
изменению положения: красно-оранжевый — размыв, синий — накопление, серый —
нейтральная зона. Единая шкала сохраняется между шагами; единицы отображаются
как `м/шаг` или `м/год`.
Текстовые блоки научной карты имеют единое левое выравнивание.
Метаданные и легенды размещаются в отдельной области над картой, чтобы не
перекрывать друг друга и не ухудшать читаемость координатной сетки.
Оси OX/OY и масштаб вынесены за пределы клиппинга карты и сохраняются при
изменении параметров сетки.
JSON-метрики содержат блок `reproducibility` с версией схемы, системой
координат, референсной точкой проекции и единицами измерения. В него также входят SHA-256 входной
геометрии, число точек, тип сетки, размер ячейки и буферная зона.
Блок `report_metadata` содержит дату формирования, версию входной геометрии
SHA-256, источник данных, идентификатор эксперимента, проекцию и её референсную
точку; эти сведения также видны в заголовке SVG.
Для `dimension` дополнительно сохраняются все уровни `ε`, значения `N(ε)` и
смещения расчётной сетки.
Легенда box-counting на карте показывает плотность покрытия ячеек, тёмной
рамкой отмечает представительный масштаб внутри регрессионного окна и содержит
ссылку на соответствующий `dimension_loglog_*.svg`.
Для наблюдаемой линии `dimension` формируется один log-log SVG-график с
регрессионным окном, а JSON содержит доверительный интервал и локальные
наклоны для оценки устойчивости размерности.
Для `erosion` JSON дополнительно содержит среднее подписанное и максимальное
абсолютное изменение береговой линии для каждого шага, а также число
контрольных наблюдений и совпадений с ними. На карте зелёные контрольные точки
означают согласие с наблюдением в пределах погрешности, оранжевые — расхождение.
Для `dimension` отображается 95%-й доверительный интервал оценки размерности.
Команда `mesh` сохраняет полные GEO/MSH-файлы в `output/mesh/`, а также
`mesh-comparison.json`, `mesh-comparison.tsv` и отдельный SVG каждого
алгоритма. Для многомиллионных сеток прореживается только обзорный SVG; MSH и
метрики рассчитываются по полному набору ячеек.
Команда `seabed render` сохраняет обзорную карту в
`output/seabed/svg/bathymetry-overview.svg`, а три непрореженных контрольных
фрагмента — в `output/seabed/svg/mesh-details.svg`. Дополнительно создаются
`seabed-3d.svg`, `profiles.svg` и обновлённый `profiles.csv`. Параметры всех
SVG, критерии выбора участков и профильных трасс записываются в
`output/seabed/bathymetry-overview.json` по схеме
`lito-bathymetry-visualization/v3`. Цвет обзора и 3D-поверхности кодирует
положительную глубину; цвет детальных ячеек — качество их формы.

### Benchmark калибровка

Историческая команда `benchmark calibrate` выполняет исследовательский подбор,
а не доказательную валидацию: параметры выбираются по взвешенному RMSE
обучающей выборки, а отложенные наблюдения по береговой линии показываются
отдельно. Наблюдения вне заданного расстояния до сегмента побережья исключаются;
при малой отложенной выборке R² и p-значение не интерпретируются. Подробные
ограничения и порядок работы приведены в [руководстве по калибровке](docs/benchmark-calibration.md).
Для каждой принятой точки используется её собственный период `start_date`—`end_date`;
JSON-отчёт и TSV-диагностика исключений автоматически сохраняются в `output/`.
Точки без положительной неопределённости исключаются, а недостаток независимых
наблюдений и чрезмерная дистанция до профиля выводятся как предупреждения качества.
Для проверки переноса общей пары параметров на независимый участок используйте
`lito benchmark cross-validate`; результат сохраняется в `output/metrics/`.
