# VIEW-03: 3D-рельеф и профили Чёрного моря

## Артефакты и запуск

VIEW-03 строится из принятого MSH `lito-seabed/v1` без повторной выборки
батиметрии:

```bash
./lito seabed render
```

Команда добавляет к обзорной карте и деталям сетки:

- `output/seabed/svg/seabed-3d.svg` — ортографический 3D-вид поверхности;
- `output/seabed/svg/profiles.svg` — карта трасс и три профильных графика;
- `output/seabed/profiles.csv` — все узлы трасс с координатами и глубинами;
- `output/seabed/bathymetry-overview.json` — общий отчёт схемы
  `lito-bathymetry-visualization/v3`.

По умолчанию 3D использует вертикальное преувеличение ×40, потому что глубина
Чёрного моря около 2,2 км несопоставима с горизонтальным размером акватории
свыше 1000 км. Коэффициент можно изменить:

```bash
./lito seabed render --vertical-exaggeration 20
./lito seabed render --vertical-exaggeration 1
./lito seabed render --control-points=false
```

Значение меньше 1, бесконечность и `NaN` отклоняются до создания файлов.

## Метрический смысл 3D

Исходные координаты не изменяются:

```text
X = x_m
Y = y_m
Z = elevation_m = −water_depth_m
```

Сначала X/Y поворачиваются в плоскости LAEA, затем применяется
ортографический наклон камеры. Вертикальная составляющая экрана вычисляется из
`Z × vertical_exaggeration`. При коэффициенте 1 горизонтальный и вертикальный
метр проходят один и тот же масштаб до наклона камеры. При коэффициенте 40
исходная отметка не переписывается: меняется только SVG-проекция.

Корневой SVG содержит `data-vertical-exaggeration`, а JSON — поля
`vertical_exaggeration` и `data_coordinates_unchanged`. Коэффициент также
крупно подписан в заголовке и легенде, поэтому преувеличенный вид нельзя
перепутать с натуральной геометрией.

Цвет поверхности означает положительную глубину. Белые, красные и тёмные
точки в режиме контроля показывают узлы MSH с билинейной, ближайшей и
береговой выборкой соответственно. Это **не полный растр GEBCO**: миллионы
исходных центров ячеек не дублируются в SVG. Точки позволяют сравнить узловые
значения, по которым построена ячеечная поверхность.

## Выбор профильных трасс

Для одинакового MSH выбор полностью воспроизводим:

1. Берутся крайние западный, восточный и северный узлы внешней береговой
   границы `coastline`. Островные и открытые границы не становятся началом.
2. Глубоководное ядро образуют узлы глубже 90% максимальной узловой глубины.
3. Для каждого берега выбирается ближайший узел ядра; по возможности конечные
   узлы трёх профилей не повторяются.
4. Путь находится по фактическим рёбрам четырёхугольных ячеек. Основной вес —
   метрическая длина ребра; повторный выход на берег и движение к меньшей
   глубине получают штраф. Это сохраняет топологическую связь с MSH и уменьшает
   бессодержательное следование вдоль берега.

Получаются профили:

- `profile-west` — западный берег → глубоководье;
- `profile-east` — восточный берег → глубоководье;
- `profile-north` — северный берег → глубоководье.

Начальный узел обязан иметь глубину 0 м, конечный — находиться в
глубоководном ядре. ID узлов, длина, число точек и критерий выбора сохраняются
в JSON. `profiles.csv` записывает накопленное расстояние LAEA, WGS 84,
`elevation_m`, `water_depth_m`, способ выборки и качество каждого узла.

## Как читать profiles.svg

Слева находится карта фактических трасс на батиметрической поверхности.
Пустой маркер обозначает начало на берегу, заполненный — конец в
глубоководном ядре. Справа три разреза используют одну вертикальную шкалу и
не имеют вертикального преувеличения (`×1`).

- горизонтальная ось — накопленное расстояние от берега, км;
- вертикальная ось — отметка относительно указанной вертикальной системы, м;
- кружки — фактические узловые выборки MSH;
- цветная линия — кусочно-линейная интерполяция между соседними узлами пути;
- голубая область — водная толща между уровнем 0 и поверхностью дна.

Широкий почти горизонтальный начальный участок показывает шельф. Резкое
падение линии соответствует материковому склону. Глубокий пологий конец
профиля относится к котловине. Локальные подъёмы могут быть реальными
особенностями дискретизированного рельефа либо следствием грубой сетки; для их
интерпретации нужно сопоставлять профиль с VIEW-02 и исходной батиметрией.

## Ограничения

Ортографический SVG помогает контролировать форму поверхности, но не является
интерактивной сценой или гидродинамической моделью. Линия профиля следует
рёбрам текущей сетки, а не обязательно геодезической нормали к берегу.
Увеличение плотности сетки не создаёт новых измерений. GEBCO не предназначен
для навигации, и все артефакты VIEW-03 нельзя использовать для задач
безопасности на море.
