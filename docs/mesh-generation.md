# Генерация и сравнение расчётных 2D-сеток

Команда `lito mesh` восстанавливает анализ всей поверхности Чёрного моря и
заменяет нарисованную поверх карты прямоугольную решётку фактическими ячейками
открытого генератора Gmsh. По умолчанию используется полный кэшированный
полигон MarineRegions: внешнее кольцо содержит 9 635 точек, острова сохраняются
как внутренние отверстия.

## Установка генератора

Gmsh распространяется по GPL v2 или более новой версии. Lito запускает его как
отдельный процесс и сохраняет все входы, журнал и результат. Официальный SDK
устанавливается только внутрь `output/mesh/tools/`:

```bash
./scripts/install-gmsh.sh
```

Путь можно задать явно флагом `--gmsh` или переменной `LITO_GMSH_PATH`. Lito
также ищет `gmsh` в `PATH` и локальный SDK в `output/mesh/tools/`.

Используемая версия зафиксирована скриптом как 4.15.2. Официальные описание,
загрузки и лицензия: [сайт Gmsh](https://gmsh.info/). Параметры алгоритмов
приведены в [справочнике Gmsh](https://gmsh.info/doc/texinfo/).

## Набор экспериментов

Полный набор масштабов из замечания научного руководителя запускается так:

```bash
./lito mesh \
  --cell-sizes 1000,500,300,200 \
  --boundary-details 1000,500,300,200 \
  --allow-large
```

Списки сопоставляются по позиции. Один допуск детализации можно применить ко
всем сеткам. По умолчанию сравниваются:

- `delaunay` — классический Delaunay;
- `frontal-quad` — Frontal-Delaunay for Quads;
- `parallelograms` — Packing of Parallelograms.

Gmsh сначала создаёт независимую смешанную сетку каждого алгоритма с шагом в
2,5 раза больше целевого. Затем Lito согласованно делит каждый треугольник и
четырёхугольник через общие середины рёбер и центр исходной ячейки. Поэтому итог
не содержит треугольников и висячих узлов, а средняя фактическая длина ребра
остаётся близкой к заданной и отдельно сохраняется в метриках.

Перед генерацией граница упрощается алгоритмом Дугласа—Пекера с явным
метрическим допуском. Рёбра короче половины допуска объединяются. Остров,
площадь которого меньше квадрата допуска, не считается устойчиво разрешимым на
этом уровне; его полная площадь входит в ошибку сохранения особенностей.
Если хорды упрощённого внешнего кольца пересекаются, Lito возвращает необходимые
исходные вершины, не увеличивая заданную погрешность. Остров, пересекающий
упрощённый берег на выбранном масштабе, исключается как неразрешимая особенность,
а его площадь полностью входит в `Σ|ΔS|`. Заданный и фактический безопасный
допуски сохраняются в JSON/TSV и подписываются на SVG.

## Критерий «наилучшего» генератора

Для каждого упрощённого ребра замыкается полигон между ним и соответствующим
фрагментом исходного берега. Основная метрика равна

```text
Σ|ΔS| = сумма абсолютных локальных изменений площади.
```

Абсолютное значение берётся до суммирования: потеря площади залива не
компенсирует увеличение соседней косы. Метрика нормируется на площадь полосы
берега шириной в одну целевую ячейку. Итоговая оценка от 0 до 100 включает:

- 55% — сохранение локальных площадей;
- 20% — RMS-погрешность фактической границы MSH относительно заданной границы;
- 20% — качество формы ячеек по отношению длин рёбер и отклонению углов от 90°;
- 5% — доля четырёхугольников.

Все генераторы получают одну и ту же топологически корректную границу, поэтому
на одном уровне `Σ|ΔS|` у них совпадает по построению. Это желательное свойство
согласованной сетки: генератор не имеет права самовольно сдвигать берег.
Метрика площади сравнивает уровни детализации, а выбор генератора внутри одного
уровня определяется качеством и устойчивостью ячеек; ошибка замыкания площади
MSH остаётся дополнительной проверкой.

ИИ намеренно не используется в базовом ранжировании. Без размеченного корпуса
«хороших» и «плохих» сеток нейросетевая оценка не воспроизводима и может
подменить геометрический критерий. JSON сохраняет формулу и веса, поэтому при
появлении экспертной разметки её можно сравнить с отдельной ML-моделью.

## Равноплощадная проекция

Полигон переводится из WGS 84 в сферическую азимутальную равноплощадную
проекцию Ламберта (LAEA) с центром по внешней границе Чёрного моря. Все координаты
GEO/MSH и длины заданы в метрах. Равноплощадность нужна, чтобы рейтинг не
зависел от широты участка. Центр проекции сохраняется в JSON.

## Выходные файлы

Все результаты находятся в `output/mesh/`:

- `geo/*.geo` — полностью воспроизводимые сценарии Gmsh;
- `msh/*.msh` — полные сетки MSH 2.2;
- `logs/*.log` — версия, параметры и сообщения генератора;
- `svg/*.svg` — обзор всей поверхности; большие сетки прореживаются только в SVG;
- `mesh-comparison.json` — метрики, пути, ранги и лучший алгоритм каждого уровня;
- `mesh-comparison.tsv` — компактная таблица сравнения.

Для полного Чёрного моря размер 200 м означает порядок 16 млн ячеек на один
алгоритм. Перед таким запуском необходимо проверить оперативную память и место
на диске. Защитный предел одного запуска задаётся `--max-cells`; осознанное
превышение требует `--allow-large`. Для быстрой проверки конвейера используйте:

```bash
./lito mesh \
  --cell-sizes 10000 \
  --boundary-details 10000 \
  --generators delaunay
```

Один запуск Gmsh по умолчанию ограничен пятью минутами
(`--generator-timeout`). Алгоритм, превысивший лимит или завершившийся ошибкой,
не останавливает сравнение остальных: причина и фактическое время сохраняются в
JSON/TSV и журнале, а неуспешный результат исключается из ранжирования.

## Связь с другими моделями

`lito dimension --full-black-sea` выполняет box-counting по всему наблюдаемому
контуру. Его квадратная сетка — аналитический инструмент подсчёта `N(ε)`, а не
расчётная 2D-сетка, поэтому она сохраняется отдельно.

Текущая `lito erosion` является одномерной one-line моделью CERC локального
участка. Сетка Gmsh не передаётся в CERC и не выдаётся за 2D-гидродинамический
расчёт. Для физического расчёта по всей акватории понадобятся отдельные
уравнения мелкой воды, граничные условия, пространственные поля волнения,
батиметрии и калибровочные данные.
