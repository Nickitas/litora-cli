# ADAPT-01: поле требуемого размера ячейки

## Назначение

ADAPT-01 формирует объяснимое скалярное поле `h(x,y)` для будущей
четырёхугольной сетки Чёрного моря. Значение `h` измеряется в метрах и задаёт
желаемую длину ребра: чем оно меньше, тем подробнее должна быть сетка.

Этап не запускает Gmsh и не изменяет существующий MSH. Он создаёт независимый
воспроизводимый вход для ADAPT-02. Поэтому карта `size-field.svg` показывает
поле задания размера на принятом батиметрическом каркасе, а не уже построенную
адаптивную сетку.

## Запуск

```bash
go build -o lito ./cmd/lito
./lito seabed adapt
```

По умолчанию читается `output/seabed/black-sea-depth.msh`, а результаты
сохраняются только в `output/seabed/`:

- `adaptive/size-field.csv` — полное узловое поле и слагаемые формулы;
- `adaptive/size-field.json` — конфигурация, формулы и статистика;
- `svg/size-field.svg` — обзорная карта целевого размера.

Основные параметры можно менять явно:

```bash
./lito seabed adapt \
  --min-size 200 \
  --coast-size 300 \
  --shelf-size 500 \
  --deep-size 1000 \
  --coast-influence 25000 \
  --curvature-reference 30 \
  --slope-reference 10 \
  --max-neighbour-ratio 1.25 \
  --max-size-gradient 0.15
```

Все размеры и расстояния задаются в метрах, углы — в градусах, а
`max-size-gradient` — в метрах изменения `h` на метр расстояния.

## Входные признаки

Расчёт выполняется в метрических координатах LAEA принятой модели
`lito-seabed/v1` и не содержит случайных чисел.

### Расстояние до берега

Для каждого узла вычисляется кратчайшее евклидово расстояние до физического
ребра `coastline` или `island`. Открытая расчётная граница берегом не считается.
Влияние берега затухает по закону

```text
Acoast = exp(-distance_to_coast / coast_influence).
```

При стандартной дальности `25 000 м` прямолинейный берег получает базовые
`300 м`, после чего влияние плавно уменьшается в сторону моря.

### Локальный поворот береговой линии

В береговом узле определяется угол отклонения соседних рёбер от прямой линии:

```text
turn = 180° - angle(edge_before, edge_after).
```

Это дискретная мера кривизны принятого берегового контура, а не аналитическая
кривизна исходного растра. Ноль соответствует прямому участку. Поворот `30°`
и больше даёт максимальный сигнал уточнения. Внутри акватории сигнал линейно
интерполируется на ближайшем береговом ребре и умножается на `Acoast`.

### Градиент глубины

Для узла берётся максимальный `slope_deg` инцидентных ячеек BATHY-03. Это
связывает ADAPT-01 с уже рассчитанной плоскостью глубин, а не повторяет
батиметрическую интерполяцию. Уклон `10°` и больше даёт максимальный сигнал.
При отсутствии глубины используется консервативное эффективное значение
`slope_reference`, а поля `depth_available` и `gradient_available` остаются
ложными в CSV. Измеренный `depth_gradient_deg` при этом не подменяется:
значение формулы хранится отдельно как `effective_gradient_deg`.

## Формула исходного размера

Сначала формируется морфометрическая основа `hbase`:

- до границы шельфа `200 м` глубины — `500 м`;
- от `200` до `2000 м` глубины — линейный рост от `500` до `1000 м`;
- от `2000 м` — `1000 м`.

Затем из основы вычитаются только объяснимые уточнения:

```text
Rdistance  = max(0, hbase - 300) * Acoast
Rcurvature = (300 - 200) * clamp(turn / 30°, 0, 1) * Acoast
Rgradient  = (500 - 300) * clamp(slope / 10°, 0, 1)

hraw = clamp(hbase - Rdistance - Rcurvature - Rgradient, 200, 1000).
```

Так прямой спокойный берег стремится к `300 м`, сложный поворот — к `200 м`,
ровный шельф — к `500 м`, а удалённая ровная котловина — к `1000 м`. Крутой
склон может быть подробнее своей глубинной основы.

CSV сохраняет `hbase`, три вычитаемых вклада, `hraw` и окончательное `h`.
Поэтому локальное значение можно восстановить независимо от SVG и генератора.

## Ограничение роста

Исходные значения распространяются по уникальным рёбрам текущего
четырёхугольного каркаса от меньшего размера к большему. Для каждого соседнего
узла действует одновременно два условия:

```text
h[j] <= h[i] * max_neighbour_ratio
h[j] <= h[i] + edge_length * max_size_gradient_per_m.
```

Стандартные пределы — `1.25` и `0.15 м/м`. Алгоритм только уменьшает слишком
крупное значение рядом с необходимой детализацией и никогда не стирает
локальный минимум. В JSON сохраняются максимальное отношение и градиент до и
после согласования, а также число изменённых узлов.

## Контрольный результат для всей акватории

Для текущего MSH Чёрного моря поле содержит `1712` узлов и `1596` ячеек.
Стандартный запуск даёт диапазон `200–999 м`, медиану около `413 м` и
корректирует рост в `1158` узлах. Итоговое максимальное отношение соседних
значений равно `1.25`, а максимальный пространственный градиент — около
`0.0258 м/м`, то есть оба заданных ограничения соблюдаются.

Береговые узлы остаются в диапазоне `200–300 м`, шельфовые — приблизительно
`310–496 м`, а ровное глубоководье достигает `999 м`. Меньшие значения внутри
глубоководной зоны являются не ошибкой классификации, а результатом
распространения требования плавного роста от близлежащей подробной области.

## Как читать карту

- тёмный бирюзовый цвет — `200–300 м`, наиболее подробная будущая сетка;
- золотистый — около `500 м`, базовый шельфовый размер;
- терракотовый — до `1000 м`, ровные удалённые глубоководные участки;
- тёмная линия — внешний берег или остров;
- внутренние рёбра исходного MSH намеренно скрыты.

Цвет кодирует размер, а не глубину, уклон или качество данных. Фактические
рёбра адаптивной сетки появятся только после ADAPT-02.

## Машинный контракт и ограничения

JSON использует схему
[`lito-adaptive-size-field-v1.schema.json`](schemas/lito-adaptive-size-field-v1.schema.json)
и всегда содержит `adaptive_mesh_generated: false`. Поле привязано к
идентификаторам узлов входного MSH; перестроенная сетка потребует повторной
выборки батиметрии согласно общему контракту.

Текущая дискретная кривизна зависит от детализации принятой береговой линии,
а градиент — от разрешения исходного батиметрического каркаса. ADAPT-03 должен
сравнивать генераторы при одном и том же CSV, иначе различия нельзя приписать
только алгоритму построения сетки.
