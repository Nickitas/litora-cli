# AI-02: проверка необходимости ML-модели

## Назначение

`lito seabed assess-ml` не ищет «лучшую нейросеть» и не меняет рейтинг
ADAPT-03. Команда проверяет более узкий научный вопрос: дают ли пять
детерминированных составляющих рейтинга дополнительную способность объяснять
независимые экспертные оценки по сравнению с одним итоговым баллом ADAPT-03.

До получения качественной разметки корректный результат — «ML не
рекомендуется». Это не ошибка и не основание заменить измеряемые
геометрические и батиметрические критерии моделью.

## Входные данные и запуск

Сначала создайте карточки AI-01, затем соберите оценки не менее чем от двух
независимых экспертов для каждой карточки. `organizer-key.json` должен
оставаться у организатора до конца разметки.

```bash
./lito seabed expert-set --levels coarse
# Эксперты заполняют output/seabed/expert-set/expert-rating-template.tsv
./lito seabed assess-ml
```

Лист оценок является настоящим TSV: его нужно заполнять в строках карточек,
сохраняя восемь столбцов. Пустые строки остаются незаполненными. Для одной
карточки добавляют отдельную строку для каждого эксперта с уникальным
идентификатором.

Команда проверяет SHA-256 закрытого ключа и принятого отчёта ADAPT-03. Поэтому
замена результата сравнения генераторов после разметки обнаруживается до
обучения.

## Признаки и независимая проверка

Экспертный целевой балл — среднее четырёх оценок 1–5: берег, изобаты, сетка и
отсутствие артефактов. Для одной карточки сначала усредняются независимые
экспертные баллы; карточка с одной оценкой не участвует в AI-02.

Набор AI-01 уже разделён географически:

| Часть | Использование |
|---|---|
| `training` | подбор коэффициентов моделей |
| `evaluation` | единственная независимая оценка ошибки и решение о ML |

Базовая прозрачная модель калибрует только детерминированный `overall`.
Кандидат — ridge-регрессия со следующими уже сохранёнными компонентами
ADAPT-03:

| Признак | Смысл |
|---|---|
| `coastline` | сохранение особенностей береговой линии |
| `bathymetry` | сохранение глубин и производных характеристик |
| `cell_geometry` | качество четырёхугольников |
| `target_size_compliance` | соответствие полю требуемого размера |
| `efficiency` | затраты времени и памяти |

Это намеренно маленькая интерпретируемая модель. Нейросеть не нужна для
первой проверки: при таком объёме экспертных карточек она не дала бы
воспроизводимого преимущества и лишь увеличила бы риск переобучения.

## Критерий решения

По умолчанию ML-кандидат рекомендуют только одновременно при всех условиях:

1. в каждой используемой карточке есть не менее двух независимых экспертов;
2. есть не менее 12 карточек `training` и 12 карточек `evaluation`;
3. на `evaluation` кандидат уменьшает RMSE не менее чем на 10 % относительно
   прозрачной базы;
4. ранговая корреляция Спирмена кандидата не ниже, чем у базы;
5. абсолютная корреляция Спирмена итогового `overall` с экспертами меньше
   0,80: если общий детерминированный показатель уже достаточен, усложнение
   модели не обосновано.

Пороги можно явно зафиксировать в воспроизводимом запуске:

```bash
./lito seabed assess-ml \
  --min-experts-per-card 2 \
  --min-training 12 \
  --min-evaluation 12 \
  --ridge-lambda 1 \
  --min-rmse-improvement 0.10
```

## Результаты

Все результаты сохраняются в `output/seabed/ai-necessity/`:

| Файл | Содержание |
|---|---|
| `ai-necessity.json` | входные SHA-256, пороги, корреляции, решение, RMSE и причины |
| `ai-necessity.tsv` | компактное табличное резюме решения |
| `model-assessment.json` | версии, признаки и коэффициенты базы и ridge-кандидата, их независимые ошибки |
| `ai-necessity.log` | краткий журнал запуска |

Контракт отчёта —
[`lito-ai-necessity/v1`](schemas/lito-ai-necessity-v1.schema.json). Даже при
отсутствии оценок создаётся отчёт и явно сохраняется отказ от рекомендации
ML; модель при этом не считается научно принятой.

## Ограничения

AI-02 оценивает только добавочную полезность предиктора для экспертного
суждения. Он не заменяет полные тесты QA-01–QA-03, сохранение площади кос и
заливов, батиметрические ошибки, проверку качества ячеек и расчётные лимиты.
Результат не предназначен для навигации или для прогноза глубин вне входной
батиметрии Чёрного моря.
