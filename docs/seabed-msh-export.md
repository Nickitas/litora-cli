# EXPORT-01: батиметрическая модель в Gmsh MSH 2.2

## Назначение

Пакет `internal/domain/seabed` экспортирует принятую модель дна Чёрного моря
в ASCII Gmsh MSH 2.2. Файл хранит не только плоскую топологию, но и отметки
дна, положительную глубину воды, происхождение узловых значений, физические
группы границ и производные характеристики четырёхугольных ячеек.

Целевой путь пользовательского пайплайна —
`output/seabed/black-sea-depth.msh`. Запись выполняет `seabed.WriteMSH2`,
обратное чтение и определение типа модели — `seabed.ReadMSH2`.

## Явное различение схем

В секции `$Comments` батиметрический файл содержит:

```text
lito_model_kind=seabed
lito_schema_version=lito-seabed/v1
lito_vertical_coordinate=elevation_m
lito_nodata_sentinel=-1
```

Там же сохраняются пороги зон `coast`, `shelf` и `slope`. Новая плоская сетка
из пакета `mesh` имеет `lito_model_kind=flat` и
`lito_schema_version=lito-mesh/v1`. Файл без обоих маркеров считается
`legacy-flat`.

Это различие принципиально: `Z = 0` плоской сетки описывает геометрический
каркас, но не является измеренной или интерполированной батиметрией. При
чтении такого файла узловые `ElevationM` и `WaterDepthM` остаются `nil`, флаг
качества равен `no_data`, а модель не получает статус `Accepted`.

## Геометрия и физические группы

В `$Nodes` записываются `X = x_m`, `Y = y_m`, `Z = elevation_m`. Вертикального
увеличения в числовых данных нет. В `$Elements` сначала идут принятые
четырёхугольники, затем граничные рёбра. Используются следующие физические
группы:

| Размерность | Код | Название | Значение |
|---:|---:|---|---|
| 1 | 1 | `Береговая линия` | внешний берег акватории |
| 1 | 2 | `Берег острова` | граница островного отверстия |
| 1 | 3 | `Открытая граница` | торец локальной расчётной области |
| 2 | 10 | `Морское дно` | четырёхугольные ячейки поверхности |

Тип хранится для каждого ребра в `seabed.Model.BoundaryEdges`. Это устраняет
неоднозначность узла на стыке берега и открытой границы.

## Узловые данные

Каждая величина хранится отдельным скалярным `$NodeData`:

| Имя | Единица/код | Правило |
|---|---|---|
| `longitude_deg` | градус | WGS 84, долгота |
| `latitude_deg` | градус | WGS 84, широта |
| `elevation_m` | м | неположительная отметка, совпадает с Z |
| `water_depth_m` | м | `max(0, -elevation_m)` |
| `sampling_method_code` | код | способ назначения значения |
| `source_distance_m` | м | расстояние или sentinel для `null` |
| `quality_code` | код | качество узлового значения |
| `boundary_code` | код | роль узла на границе |

## Данные ячеек

Каждая величина хранится отдельным скалярным `$ElementData`:

| Имя | Единица/код |
|---|---|
| `area_m2` | м² |
| `elevation_min_m`, `elevation_max_m`, `elevation_mean_m` | м |
| `water_depth_mean_m` | м |
| `slope_deg` | градус |
| `aspect_deg` | градус или sentinel для плоской ячейки |
| `roughness_m` | м |
| `region_code` | код морфометрического региона |
| `cell_quality_code` | код агрегированного качества |
| `quality_score` | от 0 до 1 |

## Таблицы кодов

Коды возвращает `seabed.DefaultMSHCodeTables`. Функция каждый раз создаёт
новые карты, поэтому внешний код не может изменить таблицы схемы.

| Поле | Значения |
|---|---|
| `sampling_method_code` | `not_sampled=0`, `exact=1`, `bilinear=2`, `nearest=3`, `irregular=4`, `coastline_constraint=5` |
| `quality_code` | `rejected=0`, `no_data=1`, `fallback=2`, `constrained=3`, `verified=4` |
| `boundary_code` | `none=0`, `coastline=1`, `island=2`, `open_boundary=3` |
| `region_code` | `unclassified=0`, `coast=1`, `shelf=2`, `slope=3`, `basin=4` |
| `cell_quality_code` | `fallback=1`, `mixed=2`, `verified=3` |

## NoData и допустимость записи

MSH создаётся только для `Model.Accepted = true` с полным покрытием узлов и
ячеек. `no_data`, `rejected`, `NaN`, бесконечности, треугольники и
несогласованные `elevation_m`/`water_depth_m` отклоняются до создания файла.

Отрицательный sentinel используется только для двух nullable-полей, где
отрицательное физическое значение недопустимо:

- `source_distance_m`: береговое условие не ссылается на исходную точку;
- `aspect_deg`: у плоской ячейки нет направления наибольшего понижения.

Значение sentinel всегда объявлено в `$Comments`; оно не используется для Z,
отметки, глубины, уклона или качества.

## Проверка round-trip

Автоматические тесты выполняют цикл `Model → MSH → Model` и сравнивают:

- число, идентификаторы, координаты и все характеристики узлов;
- четырёхугольную топологию и все производные ячеек;
- физические роли граничных рёбер;
- схему, вертикальную координату, sentinel и пороги регионов.

Расширенный файл также читается базовым `mesh.ReadMSH2`: этот путь сохраняет
только X/Y, WGS 84 и топологию и намеренно не объявляет полученный объект
батиметрической моделью.
