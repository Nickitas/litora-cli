# SVG-визуализация

Команды `lito dimension`, `lito koch-demo`, `lito erosion` и `lito mesh`
формируют карты контуров на рабочем поле.

`dimension` визуализирует неизменённую наблюдаемую линию. `koch-demo` создаёт
отдельные синтетические Кох-подобные контуры с префиксом `koch_demo_` и не
входит в научную интерпретацию природной береговой линии.

На картах отображаются текущий контур модели, аналитическая сетка, описание
эксперимента, масштаб, стороны света и значения осей OX/OY (долгота и широта в градусах соответственно).

На карте `dimension` оранжевые ячейки — покрытые ячейки `N(ε)`, участвующие в
интерпретации box-counting; оттенок показывает плотность прохождения
дискретизированной береговой линии. На карте `erosion` стрелки показывают направление волн,
а их плотность намеренно уменьшена для читаемости.

Легенда box-counting поясняет три уровня насыщенности покрытых ячеек и тёмную
рамку ячеек на представительном масштабе, который входит в регрессионное окно.
Диапазон этого окна указывается в метрах. На карту также добавляется ссылка на
соответствующий `dimension_loglog_*.svg`, где видны все масштабы и точки
регрессии.
Для шагов эрозии начиная с первого добавляется локальная карта изменения
береговой линии. Красно-оранжевые участки показывают отступ берега и размыв,
синие — смещение в сторону моря и накопление, серые — нейтральную зону, где
изменение меньше порога чувствительности. Насыщенность цвета пропорциональна
величине изменения. Максимальный диапазон шкалы одинаков для всех шагов одного
запуска, поэтому цвета можно сопоставлять между картами. По умолчанию значения
указываются в `м/шаг`; при `--years-per-step`, отличном от одного года, — в
`м/год`.
Для `dimension` в заголовке указывается 95%-й доверительный интервал оценки
`D`; если интервал не удалось оценить, это отмечается явно. Для `erosion`
контрольные наблюдения отображаются маркерами: зелёный означает согласие
модельного значения с наблюдением в пределах его погрешности, оранжевый —
расхождение. Нейтральные серые участки считаются зонами низкой устойчивости
сигнала и не интерпретируются как уверенный размыв или накопление.
Заголовок, описание эксперимента и пояснение сетки выровнены по единой левой
границе научной карты. Для метаданных и легенд резервируется отдельная область
между заголовком и картой, поэтому длинные строки источника не перекрывают
подписи сетки или береговую линию.
Оси OX/OY и масштаб располагаются вне клиппинга карты, поэтому не исчезают
при изменении размера заголовка или буферной зоны сетки.

Справочная береговая линия, графики, карточки валидации и подробные метрики
остаются в JSON- и табличных результатах, но не перекрывают научную карту.
Координатная сетка отключается в этом режиме, чтобы не смешивать её с сеткой,
которая используется для визуального объяснения box-counting.

`lito mesh` отображает фактические рёбра ячеек, прочитанные из MSH после запуска
Gmsh, а не декоративную прямоугольную решётку. Для очень больших наборов SVG
равномерно прореживает только изображаемые ячейки и подписывает это на карте;
полная сетка без прореживания остаётся в `output/mesh/msh/`. В заголовке
указываются заданный и фактический топологически безопасный допуски границы,
число точек, `Σ|ΔS|`, RMS границы и итоговая оценка генератора.

## Воспроизводимость

JSON-отчёты содержат блок `reproducibility`: версию схемы метрик, версию
приложения, системы координат, референс проекции и единицы измерения. Параметры
seed сохраняются только в учебном отчёте `koch-demo` и воспроизводимых
эрозионных расчётах; научный отчёт `dimension` их не содержит.
В блоке `report_metadata` сохраняются дата формирования отчёта, SHA-256-версия
входной геометрии, фактический источник, идентификатор эксперимента, описание
проекции и координаты её референсной точки. Эти же сведения компактно
отображаются в заголовке научной SVG-карты.
Для метрических расчётов используется локальная равнопромежуточная проекция
WGS 84 с референсом в центроиде входной геометрии; её параметры также записаны
в блоке `reproducibility`.
Для box-counting в `dimension.samples` сохраняются все пары масштаба `ε` и
покрытия `N(ε)`, а `dimension.grid_offsets` фиксирует смещения сетки.
Для наблюдаемой линии `dimension` создаётся один `dimension_loglog_0.svg` с
точками всех масштабов и выделенным регрессионным окном. Учебная команда
создаёт отдельную серию `koch_demo_loglog_*.svg`.
В JSON сохраняются стандартная ошибка наклона, 95%-й доверительный интервал и
локальные наклоны, позволяющие оценить чувствительность результата к диапазону
масштабов.
Для проверки исходных данных сохраняются SHA-256 входной геометрии и число
точек, а для сетки — её тип, размер ячейки и ширина буферной зоны в километрах.
Для эрозии в `output/metrics/erosion.metrics.json` дополнительно сохраняются
среднее подписанное изменение, максимальное абсолютное изменение и единицы
измерения каждого шага в полях `mean_change_per_unit`,
`max_abs_change_per_unit` и `change_unit`.
Для эрозии поля `control_count` и `control_matches` показывают число найденных
контрольных наблюдений и число совпадений в пределах опубликованной погрешности.

### Команды для проверки

```go
go build -o lito ./cmd/lito

# Эрозия с цветовой шкалой м/шаг:
./lito erosion --steps 4

# Эрозия с единицами м/год:
./lito erosion --steps 4 --years-per-step 2
```

```go
go build -o lito ./cmd/lito

./lito dimension --input data/black-sea-coastline.geojson

# Отдельная учебная синтетическая серия
./lito koch-demo --iterations 4
```
