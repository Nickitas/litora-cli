# QA-02: метрики сохранения рельефа

## Назначение

QA-02 проверяет, насколько модель дна Lito сохраняет отдельную опорную
батиметрическую поверхность. Это не повтор внутренней проверки ADAPT-03:
ADAPT-03 переносит одно и то же поле BATHY-03 между сетками, а QA-02 принимает
другую модель и отдельный паспорт её происхождения.

Команда:

```bash
./lito seabed validate \
  --input output/seabed/black-sea-depth.msh \
  --metadata output/seabed/export-metadata.json \
  --reference /путь/к/control/black-sea-reference.msh \
  --reference-metadata /путь/к/control/export-metadata.json \
  --reference-passport /путь/к/control/reference-passport.json \
  --size-field output/seabed/adaptive/size-field.csv \
  --size-field-report output/seabed/adaptive/size-field.json
```

Опорная и проверяемая модели должны иметь схему `lito-seabed/v1`, одну
сферическую LAEA-проекцию и одну вертикальную систему. Сравнение LAT и MSL без
явного вертикального преобразования отклоняется до расчёта.

## Контрольная выборка

Центр каждой четырёхугольной ячейки опорной модели является контрольной
точкой. Он не совпадает с узлами проверяемой сетки. Глубина проверяемой модели
восстанавливается по двум треугольникам full-quad ячейки; выход за покрытие
может использовать ближайший реальный узел только в ограниченном радиусе.
Каждая такая замена и фактическое расстояние сохраняются отдельно.

Паспорт контрольной модели использует схему `lito-relief-reference/v1`:

```json
{
  "schema_version": "lito-relief-reference/v1",
  "title": "Контрольная батиметрия Чёрного моря",
  "source_product": "название продукта или промера",
  "source_version": "зафиксированная версия",
  "dataset_sha256": "64 шестнадцатеричных символа",
  "horizontal_resolution_m": 100,
  "vertical_uncertainty_m": 5,
  "vertical_reference": "явное название вертикальной системы",
  "validation_class": "interproduct_control",
  "sampling_design": "правило формирования отложенной выборки",
  "excluded_sources": ["совпадающие исходные наборы"],
  "limitations": ["ограничения интерпретации"]
}
```

Допустимые классы:

- `independent_measurements` — независимые промеры или источник без общих
  исходных данных;
- `interproduct_control` — межпродуктовый контроль с возможной зависимостью;
- `held_out_same_product` — пространственно отложенная часть того же продукта.

Успешные метрики получают `metrics_accepted=true`. Поле
`publication_ready=true` выставляется только для класса
`independent_measurements`; красивое совпадение двух зависимых DTM не
объявляется независимой научной валидацией.

## Метрики глубины и объёма

Для ошибки `eᵢ = evaluatedᵢ − referenceᵢ` вычисляются:

- смещение `mean(eᵢ)`;
- `MAE = mean(|eᵢ|)`;
- `RMSE = sqrt(mean(eᵢ²))`;
- взвешенный площадью RMSE;
- P95 абсолютной ошибки;
- список худших локальных ячеек с `X/Y`, WGS 84 и обеими глубинами.

Объём водной толщи интегрируется по площадям опорных ячеек:

`V = Σ areaᵢ · water_depthᵢ`.

Площади считаются отдельно для интервалов между выбранными изобатами, а не
только для площади «глубже уровня». Для стандартного набора 20, 200, 1000 и
2000 м создаются зоны `0–20`, `20–200`, `200–1000`, `1000–2000` и
`2000–∞ м`.

## Расстояние изобат

Каждый четырёхугольник обеих моделей делится фиксированной диагональю на два
треугольника. Пересечения треугольных граней с заданной глубиной образуют
отрезки изобаты. Вдоль них с шагом не больше половины разрешения опорного
источника равномерно размещаются контрольные точки; для каждой рассчитывается
расстояние до ближайшего отрезка второй модели в обоих направлениях. Вес линии
поэтому определяется её длиной, а не числом рёбер более подробной сетки.

Отчёт содержит симметрические mean, P95 и максимум расстояния, длины обеих
изобат и число контрольных точек. Это расстояние между линиями в общей
равноплощадной проекции, а не разность глубины, делённая на уклон.

## Уклон, сетка и способ выборки

- Уклон проверяемой поверхности получается из градиента интерполирующего
  треугольника и сравнивается с BATHY-03 опорной ячейки.
- Доля `SamplingNearest` рассчитывается по всем назначенным узлам проверяемой
  модели; максимальное расстояние до источника сохраняется отдельно.
- Геометрическая форма оценивается функцией качества четырёхугольника
  `0…1`, где квадрат равен `1`; mean и P05 приводятся для всей сетки и каждой
  морфометрической зоны.
- Фактические рёбра сопоставляются полю ADAPT-01. Для каждой зоны сохраняются
  min/P05/mean/P95/max, отношение `actual/target` и доля диапазона `0,5–1,5`.

## Пороги, связанные с источником

Пороги записываются в JSON вместе с формулой, поэтому их нельзя незаметно
заменить после расчёта:

- `depth_rmse_max = hypot(2σz, resolution · tan(P95_slope))`;
- `depth_p95_max = 1,5 · depth_rmse_max`;
- `volume_deviation_max = 100 · 2σz · Σarea / Vref`;
- `slope_rmse_max = atan(2σz / resolution)`;
- `isobath_p95_distance_max = 2 · resolution`;
- допуск площади зоны равен площади коридора шириной `±resolution` вдоль её
  опорных изобат, делённой на площадь зоны.

Здесь `resolution` и `σz` берутся только из паспорта контрольного источника.
Это проектные критерии разрешимости, а не универсальные нормативы точности
гидрографических съёмок. Фиксированные геометрические ворота Lito:

- доля ближайших замен — не более 5%;
- P05 качества четырёхугольников — не менее 0,2;
- не менее 80% наблюдений рёбер в диапазоне `0,5–1,5` от цели.

## Выходные файлы

Команда сохраняет:

- `output/seabed/quality/relief-quality.json` — полный отчёт
  `lito-relief-quality/v1`, паспорта, SHA-256 входов, пороги и локальные ошибки;
- `output/seabed/quality/relief-quality.tsv` — плоскую таблицу ключевых метрик.

Непрохождение порога возвращает ошибку команды после записи обоих отчётов.
Отсутствие локальной опорной модели EMODnet/промеров не заменяется
синтетическими данными: реализация QA-02 готова, а фактический полный прогон
по Чёрному морю относится к QA-03 и требует отдельно подготовленного
контрольного набора.

## Ограничения источников Чёрного моря

GEBCO и EMODnet частично используют общие данные. При контроле GEBCO по
EMODnet необходимо исключать ячейки EMODnet с `Source Reference = GEBCO` и
фиксировать это в `excluded_sources`. Даже после исключения результат следует
называть межпродуктовым контролем, если независимость всех исходных промеров
не доказана. Для публикационной проверки предпочтительны зафиксированные
рейсовые профили или промеры с документированной вертикальной системой.
