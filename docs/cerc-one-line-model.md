# Инженерная одномерная модель CERC

Команды `lito erosion` и `lito all` используют инженерную модель одной линии
берега. Она предназначена для вдольбереговой перестройки песчаного берега на
масштабе, для которого профиль можно считать сохраняющим форму. Это не 2D
морфодинамическая модель и не заменяет полевые измерения.

## Необходимые данные

Расчёт не начинается без двух явно загруженных входов:

- батиметрии в JSON-формате Lito;
- временного ряда состояний волн через `--wave-input`.

Исключение сделано только для пустого запуска `lito erosion` или `lito all`:
он автоматически выбирает поставляемый стартовый участок Сочи. Программа
берёт его валидируемый локальный кэш либо при первом запуске скачивает открытые
данные. Обновить кэш можно флагом `--refresh`. Это удобная техническая
демонстрация со статусом `demo`, а не исследовательский сценарий: источник
волн представляет собой оперативный прогноз, а не архив наблюдений или
реанализ.

Линия берега должна быть незамкнутым, последовательно оцифрованным **локальным
сегментом**. Обзорный `data/black-sea.json` описывает весь бассейн редкими
вершинами и не является допустимым входом one-line модели: сначала извлеките
участок исследования с непрерывной береговой линией и подготовьте для него
прибрежную батиметрию.

Для Чёрного моря рекомендуемый источник волнового ряда — реанализ
[Copernicus Marine BLKSEA_MULTIYEAR_WAV_007_006](https://data.marine.copernicus.eu/product/BLKSEA_MULTIYEAR_WAV_007_006/description).
Он публикует значительную высоту, период и направление волн. Для батиметрии
следует использовать [GEBCO Grid](https://www.gebco.net/data_and_products/gridded_bathymetry_data/): это открытая глобальная сетка с шагом 15 угловых секунд. Метаданные набора, период, дата выгрузки и способ пространственной выборки должны быть указаны в поле `source` волнового ряда и в журнале эксперимента.

Пример JSON:

```json
{
  "source": "Copernicus Marine BLKSEA_MULTIYEAR_WAV_007_006, выборка 41.80N 41.70E, 2020-01-01..2020-01-02",
  "conditions": [
    {
      "time": "2020-01-01T00:00:00Z",
      "duration_hours": 3,
      "hs_m": 1.2,
      "tp_s": 5.8,
      "direction_from_deg": 110
    }
  ]
}
```

Эквивалентный CSV обязан иметь заголовок:

```text
time,duration_hours,hs_m,tp_s,direction_from_deg
2020-01-01T00:00:00Z,3,1.2,5.8,110
```

Для CSV происхождение обязательно передаётся отдельным флагом `--wave-source`.
Направление — метеорологическое: оно указывает, **откуда** пришла волна, по
часовой стрелке от севера.

Дополнительно `LoadWaveClimate` принимает исходный JSON-ответ
[Open-Meteo Marine](https://open-meteo.com/en/docs/marine-weather-api) с
почасовыми полями `wave_height`, `wave_period`, `wave_direction`. Для него
обязательно передайте `--wave-source`, поскольку ответ API не содержит
достаточных метаданных для воспроизводимого научного отчёта. Сам факт
успешной загрузки такого ответа и завершения CERC не меняет класс сценария.

`time` либо должен присутствовать у каждого состояния, либо отсутствовать у
всех. При наличии временных меток Lito отвергает перекрывающиеся и
неупорядоченные интервалы, а в итоговом JSON показывает длительность и самый
длинный пропуск ряда.

## Расчёт

В глубокой воде спектральное состояние представлено его интегральными
параметрами `Hs` и `Tp`. Для каждого узла линии берега модель:

1. решает дисперсионное соотношение `ω² = gk tanh(kh)` и получает фазовую и
   групповую скорости;
2. преобразует угол по закону Снеллиуса;
3. получает высоту при подходе к берегу из сохранения потока энергии;
4. находит глубину разрушения из критерия `Hb = γ hb`;
5. вычисляет поток наносов CERC:

   `Q = K · (E Cg sin(αb) cos(αb)) / ((ρs − ρ) g (1 − p))`;

6. применяет дискретное уравнение неразрывности `ΔV = (Qleft − Qright) Δt`;
7. переводит объём ячейки в смещение линии через активную высоту профиля
   `B + Dc`.

`longshore-cerc.json` в `output/erosion/` содержит `scenario_status`,
`usage_limitations`, происхождение волнового ряда и батиметрии, каждую ячейку,
`Q` в `м³/с`, объём в `м³`, смещение в
метрах, дистанцию до батиметрической точки и невязку массы. Если для
билинейной интерполяции у берега не хватает ячеек, допускается только ближайшее
реальное измерение в радиусе `--max-bathymetry-gap` (по умолчанию 1500 м);
превышение радиуса останавливает расчёт. По умолчанию на концах
сегмента стоят непроницаемые границы (`Q = 0`), поэтому суммарная невязка
должна быть близка к машинному нулю.

## Качество входов и границы сегмента

Укажите фактический шаг регулярной сетки через `--bathymetry-resolution`.
Этот параметр нельзя заменять произвольным значением: от него зависит ключ
ячейки, интерполяция глубин и допустимость ближайшей точки. Для пользовательского
набора Чёрного моря он обязателен; автоматический набор Сочи задаёт свой шаг
`0.005°` явно.

В `input_quality` файла `longshore-cerc.json` фиксируются временное покрытие
волн, число точек и шаг батиметрии, доля интерполированных выборок и максимум
дистанции до ближайшего измерения. Если последняя величина велика относительно
размеров береговой формы, результат пригоден только для предварительной
оценки.

`scenario_status` описывает допустимую интерпретацию отдельно от технического
успеха расчёта. Автоматический набор Сочи получает `demo`; пользовательский
набор без отдельной процедуры аттестации получает `unclassified`. Lito не
присваивает исследовательский статус автоматически.

По умолчанию граничный поток на обоих торцах равен нулю. Для участка с
известным внешним балансом используйте:

```bash
--left-boundary-transport 0.03 \
--right-boundary-transport 0.01
```

Единица — `м³/с`; положительный поток на левой границе входит в сегмент, а на
правой — выходит из него. В отчёте сохраняются внешний чистый объём и невязка
замыкания баланса. Не задавайте эти значения без измерений или обоснованной
оценки: ноль остаётся более честным условием при отсутствии информации.

Внешние источники и стоки внутри сегмента передаются отдельным JSON-файлом:

```json
[
  {
    "point_index": 12,
    "source_rate_m3_s": 0.005,
    "description": "питание пляжа",
    "data_source": "проектный журнал работ, август 2026"
  }
]
```

Передайте его через `--sediment-sources источники.json`. Положительное значение
добавляет наносы, отрицательное моделирует их изъятие. Индекс относится к
вершине входного незамкнутого сегмента; один индекс может иметь только один
источник. Данные о происхождении обязательны. В поле `sediment_sources` и в
каждом шаге JSON-отчёта сохраняются исходные параметры и фактический внешний
объём. Профиль активного слоя и исчерпание местного запаса пока не моделируются,
поэтому не используйте этот механизм как замену инженерной оценки запасов.

Сооружения задаются отдельно на грани между `left_point_index` и следующим
узлом сегмента:

```json
[
  {
    "left_point_index": 8,
    "transmission_coefficient": 0.25,
    "kind": "буна",
    "description": "железобетонная буна",
    "data_source": "обследование сооружений, август 2026"
  }
]
```

Передайте профиль через `--structures сооружения.json`. Коэффициент `0`
означает полное перекрытие переноса, `1` — отсутствие влияния, промежуточное
значение — долю пропуска. Допускается только одно сооружение на грани, а
`kind` и `data_source` обязательны. Это one-line представление перехвата
вдольберегового транспорта: оно не рассчитывает дифракцию, отражение или
обтекание волн вокруг сооружения.

Для автоматического сценария `--black-sea-sochi` отдельный файл не
нужен: Lito загружает OSM-инвентарь сам и сохраняет ответ, производный профиль
и манифест в `data/black-sea/sochi/`. Автоматически применяется только
берегопримыкающий объект `man_made=groyne` с коэффициентом `0`; это явное
консервативное правило, а не измерение проницаемости. Волноломы сохраняются в
инвентаре, но не меняют расчёт без отдельного обоснования. При временном
лимите Overpass программа использует ранее скачанный кэш; если кэша нет,
выдаёт предупреждение и запускает расчёт без сооружений, не подменяя их
синтетическим барьером.

## Калибровка коэффициента CERC

Команда `calibrate-cerc` сопоставляет результаты физической one-line модели с
независимыми скоростями изменения линии берега и ранжирует кандидаты `K` по
RMSE. Она не использует историческую эвристику `erosion-strength`.

```bash
./lito calibrate-cerc \
  --input участок.geojson \
  --bathymetry глубины.json \
  --bathymetry-resolution 0.000139 \
  --wave-input волны-за-год.json \
  --observations наблюдения-берега.json \
  --cerc-coefficients 0.20,0.30,0.39,0.50 \
  --output output/калибровка
```

Файл наблюдений — массив JSON-объектов:

```json
[
  {
    "lat": 43.6123,
    "lon": 39.7012,
    "shoreline_change_rate_m_per_year": 0.8,
    "uncertainty_m_per_year": 0.2
  }
]
```

Положительная скорость наблюдения означает размыв, отрицательная — аккумуляцию.
Внутреннее положительное смещение CERC направлено в море и поэтому означает
аккумуляцию; при сравнении с наблюдениями программа меняет знак явно. Ряд волн
должен покрывать не меньше 8766 часов по умолчанию; семидневный прогноз Сочи
для калибровки сознательно отклоняется. Результат сохраняется в
`output/erosion/cerc-calibration.json` вместе с источниками берега и волн.

## Запуск

```bash
./lito erosion \
  --input /путь/к/локальному-сегменту.geojson \
  --bathymetry output/source/black-sea-bathymetry-gebco2026-0.01deg-derived.json \
  --wave-input /путь/к/black-sea-wave-climate.json \
  --breaking-index 0.78 \
  --berm-height 2 \
  --closure-depth 8 \
  --porosity 0.40 \
  --cerc-coefficient 0.39
```

Для быстрого запуска встроенного сценария Чёрного моря используйте:

```bash
./lito erosion --black-sea-sochi --output output/sochi-auto
```

Он загружает прогноз Open-Meteo Marine и семь морских глубин EMODnet для
Сочи, сохраняет файлы и манифест в `data/black-sea/sochi/`, а для расчёта по
умолчанию использует первые 24 часа. Режим имеет статус `demo`, намеренно
ограничен технической демонстрацией и не заменяет архивный волновой ряд,
детальную батиметрическую съёмку, калибровку или публикационное исследование.

Для исследовательского набора рядом с батиметрическим JSON обязателен паспорт
`.metadata.json`. Формат, проверка SHA-256 и отличие целевого шага 0,01° от
официальной сетки GEBCO 15 угловых секунд описаны в
[`docs/data-provenance.md`](data-provenance.md).

Модель поддерживает только участки Чёрного моря. Координаты другого бассейна
отклоняются загрузчиками береговой линии и батиметрии; переключателя акватории
в CLI нет.

`--steps 0` использует весь ряд; положительное значение является явным
ограничением первыми состояниями ряда. Временной масштаб задаётся только
`duration_hours`, поэтому эвристические флаги штормов, сезонности и подъёма
уровня моря для этой команды не применяются.

## Границы применимости

Следующее описание относится к модели при наличии подходящих входов, а не к
автоматическому сценарию Сочи со статусом `demo`.

Модель пригодна для скринингового инженерного прогноза и калибровки участка,
если есть достоверные `Hs`, `Tp`, направление, прибрежная батиметрия и
сведения об активном профиле. Перед принятием проектного решения нужно
калибровать `K`, глубину замыкания и берму по наблюдениям конкретного участка.

Она пока не моделирует дифракцию за сооружениями, отражение, нерегулярный
полный спектр, кросс-береговой перенос, изменение дна, исчерпание местного
запаса наносов и 2D-гидродинамику. Эти процессы потребуют отдельной
2D-морфодинамической ветви с регулярной сеткой, граничными условиями и
калибровочными наблюдениями.
