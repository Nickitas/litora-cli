# BATHY-01/BATHY-02: привязка глубины и согласование береговой маски

## Назначение

Модуль `internal/domain/seabed` связывает геопривязанную сетку Чёрного моря с
регулярной батиметрией GEBCO. Он не меняет исходный набор и не превращает
интерполированную сетку 200–300 м в измерения такого разрешения. Результат
сохраняет способ назначения, расстояние до исходной точки и флаг качества
каждого узла.

Обработка выполняется после `lito mesh`, потому что топология акватории и
наблюдаемая батиметрия имеют разные источники и разные маски.

## Привязка батиметрии к узлам

`seabed.RegularGridSampler` использует `geometry.BathymetryGrid` и различает:

- `exact` — узел совпал с исходной точкой;
- `bilinear` — значение получено по четырём узлам регулярной сетки;
- `nearest` — в интерполяционной ячейке есть пропуск, поэтому использована
  ближайшая исходная точка в пределах заданного радиуса.

Для билинейного значения `source_distance_m` равен расстоянию до ближайшей из
четырёх участвовавших точек. Для ближайшей замены это расстояние до самой
замены. Интерфейс `ElevationSampler` допускает отдельную реализацию
`irregular`, но выбранный источник GEBCO является регулярным, поэтому
нерегулярный интерполятор сейчас не нужен.

Если источник не покрывает узел, `elevation_m` и `water_depth_m` остаются
`null`, `sampling_method` получает `not_sampled`, а `quality_flag` — `no_data`.
Ноль не используется как значение пропуска.

## Классификация границ

Граничные рёбра MSH разбиваются на связные компоненты:

1. наибольшее замкнутое кольцо считается внешним берегом `coastline`;
2. остальные замкнутые кольца считаются островными отверстиями `island`;
3. незамкнутые цепочки считаются `open_boundary`.

Для локального участка берег и искусственные боковые стороны часто вместе
образуют одно замкнутое кольцо. Топология не позволяет угадать их физический
смысл, поэтому `BuildConfig.BoundaryOverrides` явно маркирует открытые рёбра.
Узел на стыке открытого и берегового рёбер получает `open_boundary`, чтобы к
нему не применялось нулевое береговое условие.

Береговые и островные узлы получают:

```text
elevation_m = 0
water_depth_m = 0
sampling_method = coastline_constraint
quality_flag = constrained
```

Исходная выборка такого узла, если она доступна, сохраняется в журнале как
`original_elevation_m`. Поэтому назначение берегового нуля остаётся видимым
исправлением, даже когда оно совпало с исходным значением.

## Несовпадение масок и плавный переход

Конвертер GEBCO ещё на этапе DATA-02 оставляет только конечные значения
`elevation_m < 0`, поэтому положительные значения суши не попадают во
внутренний батиметрический набор. На этапе BATHY-02 дополнительно действуют
следующие правила:

- узел, который не входит ни в одну расчётную ячейку акватории, отклоняется;
- положительная отметка внутри водной сетки отклоняется как несовпадение масок;
- отвергнутое значение становится `null`, а не нулевой глубиной;
- отрицательные значения назначаются только активным узлам водных ячеек.

Резкая замена отрицательной отметки на ноль могла бы создать ступень у берега.
Поэтому для внутренних узлов в переходной полосе используется функция
smoothstep:

```text
t = distance_to_coast_m / transition_width_m
s(t) = t² · (3 − 2t)
elevation_corrected_m = elevation_source_m · s(t),  0 < t < 1
```

`distance_to_coast_m` вычисляется алгоритмом Дейкстры по рёбрам ячеек от всех
узлов берега и островов. Это расстояние проходит внутри расчётной области и не
требует квадратичного сравнения каждого узла со всеми береговыми сегментами.
Если ширина не задана, используется две средние длины ребра текущей сетки.

Так как исходная отметка неположительна, а `0 < s(t) < 1`, исправленная отметка
всегда не глубже исходной. Поле `deepened_node_count` контролирует это
инвариантное условие и для принятого результата равно нулю.

## Диагностика и экспорт

`seabed.Model` содержит:

- статистику покрытия и способов выборки;
- число береговых, островных и открытых узлов;
- число исправлений каждого вида;
- максимальную абсолютную поправку;
- полный список исправлений с исходной и итоговой отметками.

Доступны независимые экспортёры:

- `WriteNodeDepthCSV` → `output/seabed/.../node-depth.csv`;
- `WriteCorrectionsCSV` →
  `output/seabed/.../reconciliation-corrections.csv`;
- `WriteReconciliationJSON` →
  `output/seabed/.../reconciliation-report.json`.

Сводный `seabed-quality.json` по схеме `lito-seabed/v1` хранит агрегаты и путь
к полному CSV-журналу, чтобы не дублировать большой прибрежный слой в JSON.
Подключение этих экспортёров к пользовательской команде выполняется в
`CLI-01`; запись глубины в MSH относится к `EXPORT-01`.

## Проверки

Тесты пакета подтверждают:

- непрерывный ноль внешнего и островного берега;
- отдельную обработку открытой границы;
- отсутствие неявного нуля для NoData и положительной отметки в воде;
- отсутствие созданных коррекцией провалов;
- восстановление наклонной плоскости и известную погрешность билинейной
  аппроксимации аналитической чаши;
- полный состав CSV/JSON-журнала исправлений.
