# VIEW-01: обзорная батиметрическая карта Чёрного моря

## Назначение

Обзорная карта отвечает на вопрос «где находятся мелководье, шельф,
материковый склон и глубоководная котловина» без плотной паутины рёбер. Она
строится только из принятой модели `lito-seabed/v1`, поэтому плоский MSH с
`Z = 0` нельзя случайно выдать за рельеф дна.

Основной артефакт:
`output/seabed/svg/bathymetry-overview.svg`. Рядом сохраняется машинный отчёт
`output/seabed/bathymetry-overview.json` с входными файлами, источником,
уровнями изобат, диапазоном глубин и долей NoData.

## Построение

После EXPORT-01 и EXPORT-02 карту можно повторно создать без пересчёта глубин:

```bash
go build -o lito ./cmd/lito
./lito seabed render
```

По умолчанию команда читает:

- `output/seabed/black-sea-depth.msh`;
- `output/seabed/export-metadata.json`;
- `data/black-sea-bathymetry-source.metadata.json`.

Другой принятый MSH и его паспорт задаются явно:

```bash
./lito seabed render \
  --input output/seabed/black-sea-depth.msh \
  --metadata output/seabed/export-metadata.json \
  --isobaths 20,50,100,200,500,1000,1500,2000
```

`--source-metadata` должен ссылаться на паспорт с атрибуцией и SHA-256.
Для разового проверенного источника можно передать текст `--source`, но тогда
контрольная сумма в карте отсутствует.

## Как читать карту

- Светло-бирюзовые тона показывают прибрежные глубины. Стандартная граница
  прибрежной зоны — 20 м.
- Переход от бирюзового к синему в диапазоне 20–200 м соответствует шельфу.
- Быстрое потемнение между 200 и 2000 м показывает материковый склон.
- Самые тёмные области глубже 2000 м относятся к глубоководной котловине.
- Белые линии — изобаты. Число на подписи является положительной глубиной в
  метрах, а не отрицательной отметкой `elevation_m`.
- Тёмная внешняя линия — берег акватории; берег острова имеет отдельный класс,
  открытая граница локальной модели отображается штриховой линией.
- `NoData узлов` и `NoData ячеек` показывают долю отсутствующих значений. Ноль
  означает полное покрытие, но не доказывает одинаковое качество измерений.

Цвет каждой четырёхугольной ячейки определяется её средней положительной
глубиной. Небольшая мозаичность является дискретизацией модели, а не волнами,
фрактальным узором или отдельными объектами дна. Цветовая функция непрерывна
по числовой глубине; её предел и единица всегда записаны в легенде.

## Изобаты и экранный масштаб

Изобаты вычисляются по четырём узловым глубинам каждой ячейки. Пересечение
уровня с ребром находится линейной интерполяцией, после чего отрезки соседних
ячеек образуют линию равной глубины. Это реальные производные текущей модели,
а не декоративные параллельные линии.

Внутренние рёбра сетки в VIEW-01 не рисуются вообще. Тонкая обводка того же
цвета, что и заливка ячейки, только закрывает антиалиасинговые щели SVG и не
кодирует топологию. Фактические рёбра остаются без потерь в MSH/VTU; их
непрореженные увеличенные фрагменты относятся к VIEW-02.

## Происхождение и ограничения

Карта переносит из `export-metadata.json` проекцию LAEA, вертикальную систему
и единицы. Атрибуция и сокращённый SHA-256 берутся из паспорта основного
источника GEBCO_2026. Шаг GEBCO 15 угловых секунд не равен разрешению всех
исходных промеров. Сетка 200–300 м может точнее следовать берегу, но не создаёт
новую измеренную детальность рельефа.

Карта предназначена для научного контроля модели и не может использоваться
для навигации или задач безопасности на море.

## Удалённый устаревший путь

Из прежнего универсального SVG-рендерера удалены неработающий контейнер
`IsolineOptions`, который создавался без батиметрической сетки, его заглушка
`buildIsolines` и демонстрационный файл с синтетическими англоязычными
примерами. Также локализован остававшийся английский шаблон справки Cobra. В
рабочем приложении изобаты теперь строятся только новым рендерером из узлов
`lito-seabed/v1`.
