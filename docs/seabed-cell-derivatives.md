# BATHY-03: производные характеристики ячеек морского дна

## Назначение

После назначения и берегового согласования узловых отметок пакет
`internal/domain/seabed` вычисляет характеристики каждой принятой
четырёхугольной ячейки. Расчёт использует только итоговые значения узлов и
координаты `X/Y` в равноплощадной LAEA-проекции, поэтому повторный запуск с теми
же входами даёт те же результаты.

Ячейка с хотя бы одним `NoData`-узлом не получает синтетическую глубину и не
экспортируется в `cells.csv`. Она учитывается в `no_data_cell_count`, а модель
не получает статус принятой.

## Площадь и глубина

Площадь `area_m2` вычисляется по формуле Гаусса в порядке обхода четырёх узлов:

```text
area_m2 = 0.5 · |Σ(xᵢ·yᵢ₊₁ − xᵢ₊₁·yᵢ)|
```

Узлы должны быть уникальными, а площадь — строго положительной. Минимальная,
максимальная и средняя отметки вычисляются непосредственно по четырём
`elevation_m`. Средняя положительная глубина определяется как:

```text
water_depth_mean_m = max(0, -elevation_mean_m)
```

## Уклон и экспозиция

Через четыре узла методом наименьших квадратов проводится плоскость:

```text
z = a·x + b·y + c
```

Уклон поверхности:

```text
slope_deg = atan(sqrt(a² + b²)) · 180 / π
```

Экспозиция задаёт азимут наибольшего понижения. Вектор понижения равен
`(-a, -b)`, где `X` направлен на восток, а `Y` — на север. Азимут отсчитывается
по часовой стрелке: `0°` — север, `90°` — восток. Для плоской ячейки
`aspect_deg = null`, потому что направление понижения не определено.

## Шероховатость

`roughness_m` не смешивается с общим уклоном поверхности. Она равна
среднеквадратическому остатку узловых отметок относительно найденной плоскости:

```text
roughness_m = sqrt(Σ(zᵢ − z_planeᵢ)² / 4)
```

Поэтому любая точная наклонная плоскость имеет нулевую шероховатость, а
неплоский четырёхугольник — положительную.

## Морфометрические зоны

Стандартные пороги `DefaultRegionThresholds()`:

| Зона | Условие по средней глубине |
|---|---:|
| `coast` | до 20 м включительно |
| `shelf` | свыше 20 до 200 м включительно |
| `slope` | свыше 200 до 2000 м включительно |
| `basin` | свыше 2000 м |

Ячейка, содержащая узел `coastline` или `island`, всегда относится к `coast`
независимо от средней глубины. Это сохраняет топологический смысл береговой
полосы на грубых сетках. Пороги задаются через `BuildConfig.RegionThresholds`,
должны удовлетворять `0 ≤ coast < shelf < slope` и записываются в метаданные.

Эти классы являются воспроизводимыми морфометрическими диапазонами, а не
автоматическим геологическим выделением реальной бровки шельфа или подошвы
материкового склона. Для научной интерпретации границы следует калибровать по
региональным данным.

## Качество ячейки

Категориальный `quality_flag` агрегирует четыре узла:

- `verified` — все узлы имеют проверенные значения;
- `fallback` — все узлы получены ближайшей заменой;
- `mixed` — любое сочетание разных источников либо береговых коррекций.

Численный `quality_score` равен среднему узловых весов:

| Узловое происхождение | Вес |
|---|---:|
| точное | 1,00 |
| билинейное | 0,95 |
| нерегулярное | 0,90 |
| береговое/переходное ограничение | 0,80 |
| ближайшая замена | 0,60 |

Вес является прозрачным техническим индикатором происхождения, а не оценкой
фактической вертикальной погрешности GEBCO.

## Метаданные и экспорт

`CellDerivationMetadata` сохраняет формулы, единицы, соглашение об экспозиции,
пороговые глубины, покрытие, число регионов и диапазоны уклона/шероховатости.
Те же поля входят в блок `cell_derivation` отчёта `lito-seabed/v1`.

Экспортёры:

- `WriteCellsCSV` → `output/seabed/.../cells.csv`;
- `WriteCellDerivationJSON` →
  `output/seabed/.../cell-derivation.json`.

Запись полей в `$ElementData` MSH реализована в `EXPORT-01`. `EXPORT-02`
дублирует их как `CellData` VTU и в обогащённом `cells.csv`; точный состав
описан в [`docs/seabed-vtu-csv-export.md`](seabed-vtu-csv-export.md).
