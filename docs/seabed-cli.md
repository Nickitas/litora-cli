# CLI-01: команды `lito seabed`

## Назначение

Группа `lito seabed` обрабатывает только Чёрное море. Она разделяет создание
модели дна, её научную проверку и визуализацию: один этап не может незаметно
изменить результат другого.

## Воспроизводимый путь

После создания плоской full-quad сетки командой `lito mesh` выберите MSH
нужного запуска из `output/mesh/mesh-comparison.json` и выполните:

```bash
./lito seabed build \
  --mesh output/mesh/msh/black-sea-edge-1000-detail-1000-frontal-quad.msh

./lito seabed render
```

Стандартные пути `--bathymetry` и `--bathymetry-metadata` указывают на
зафиксированный производный набор GEBCO_2026 с шагом 0,02°. Это не нативное
разрешение GEBCO. При использовании другого производного шага, в том числе
созданного из чистого каталога набора 0,01°, требуется указать оба файла и
действующий паспорт с SHA-256.

Для независимой проверки рельефа нужен отдельный опорный MSH и паспорт
происхождения:

```bash
./lito seabed validate \
  --reference /путь/к/black-sea-reference.msh \
  --reference-passport /путь/к/reference-passport.json
```

Контрольный полный запуск уровня 1000 м не заменяет эту независимую проверку:

```bash
./lito seabed check-full
```

## `seabed build`

Команда читает плоский MSH `lito-mesh/v1`, назначает глубины BATHY-01,
согласует береговую маску BATHY-02, рассчитывает производные ячеек BATHY-03
и создаёт экспорт EXPORT-01/EXPORT-02.

Если старый MSH не содержит блоков `longitude_deg` и `latitude_deg`,
`--recover-wgs84=true` восстанавливает их из `--coastline` и той же
равноплощадной LAEA-проекции. В `build-report.json` это фиксируется полем
`coordinates_recovered_from_laea`. Когда WGS 84 уже записана в MSH, команда
проверяет её согласованность с LAEA исходного контура с допуском 0,25 м.

Команда отвергает MSH, уже содержащий модель дна: повторно назначать глубины
существующей модели нельзя. Для неё предназначены `seabed render`,
`seabed adapt`, `seabed generate-adaptive` или `seabed validate`.

Результаты одного запуска хранятся в каталоге `output/seabed/`:

- `black-sea-depth.msh` — модель `lito-seabed/v1`;
- `black-sea-depth.vtu`, `nodes.csv`, `cells.csv`, `profiles.csv` — экспорт;
- `export-metadata.json` — системы координат, вертикальный датум и коды;
- `reconciliation.json` и `reconciliation-corrections.csv` — все береговые
  ограничения и плавные поправки;
- `cell-derivation.json` — площадь, глубина, уклон, экспозиция, шероховатость
  и морфометрические зоны;
- `build-report.json` и `build.log` — контрольные суммы входов, оценка
  ресурсов, фактическая память, длительность и статус принятия.

## Защитные лимиты и тихий режим

Перед созданием файлов `seabed build` проверяет:

- `--max-nodes` — не более 5 000 000 узлов по умолчанию;
- `--max-cells` — не более 5 000 000 ячеек по умолчанию;
- `--max-output-mib` — оценку полного набора экспортов, по умолчанию
  2 048 МиБ;
- `--output` — путь обязан находиться внутри `output/`.

Превышение любого порога прекращает запуск до назначения глубин. Осознанно
снять эти ограничения можно только флагом `--allow-large`; это решение
фиксируется в `build-report.json`.

Общий флаг `--quiet` подавляет терминальный вывод всех подкоманд `seabed`, но
не отменяет запись MSH, таблиц, JSON и журналов. Например:

```bash
./lito seabed build --quiet
```

## Роли остальных команд

- `seabed render` читает принятую модель и создаёт SVG-карту, фактические
  фрагменты сетки, 3D-рельеф и профили; глубины не пересчитываются.
- `seabed validate` сравнивает модель с отдельной опорной батиметрией и
  отделяет системные метрики от независимой публикационной проверки.
- `seabed adapt` строит поле требуемого размера ячейки, а
  `seabed generate-adaptive` передаёт это поле в Gmsh.
- `seabed compare-adaptive` ранжирует генераторы по сохранению рельефа и
  качеству адаптивной сетки.
- `seabed check-full` выполняет QA-03 для зафиксированной контрольной сетки
  1000 м, включая топологию, площадь, объём, визуализации и журнал ресурсов.

Научный смысл выходных полей, чтение SVG, границы применимости и полный
сценарий с чистого каталога описаны в
[`seabed-scientific-guide.md`](seabed-scientific-guide.md).
